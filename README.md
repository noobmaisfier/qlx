# QLX

**Type-safe, schema-first PostgreSQL query builder for Go.**
SQL-like DSL, compile-time checks, an analyzer for what types cannot see, and
pgx v5 at the edge. Zero reflection, minimal allocations, PostgreSQL 16–19.

QLX turns your schema into typed Go. Columns know their operations, nullable
columns cannot receive a plain value, and a required `INSERT` column cannot be
forgotten. The analyzer catches the SQL mistakes the Go compiler cannot, and a
real `PREPARE` checks the rest in tests.

> **Status: pre-release.** Current release: `v0.27.0`. The core, generator,
> executor and analyzer are verified on PostgreSQL 16, 17, 18 and 19. See
> [Verification](#verification) for what has been run.

## Quick start

```bash
go get github.com/noobmaisfier/qlx
go install github.com/noobmaisfier/qlx/cmd/qlx@latest

qlx init     # writes qlx.yaml and migrations/001_init.sql (never overwrites)
# write your schema in migrations/*.sql
qlx gen      # writes the typed package and schema.lock
qlx check    # CI: fails if generated code or schema.lock is stale
```

Requirements: Go 1.27 or later and PostgreSQL 16–19. `qlx gen` needs PostgreSQL
server binaries, or a live database through `database_url`.

Connect once, then use `client` everywhere:

```go
import (
    "os"

    q "github.com/noobmaisfier/qlx"
    "github.com/noobmaisfier/qlx/pgxexec"
    "github.com/noobmaisfier/qlx/qt"
    "example.com/app/db" // generated by `qlx gen`
)

type UserRow struct {
    ID    int64  `db:"id"`
    Email string `db:"email"`
}

client, err := pgxexec.Connect(ctx, os.Getenv("DATABASE_URL"), pgxexec.ConnectOptions{
    Spec:      &db.Spec, // version targets and table fingerprints
    MinServer: 16,
})
if err != nil {
    return err
}
defer client.Close()
```

The generated tables `db.Users`, `db.Orders`, ... are shown as `Users`,
`Orders`, ... below. Because they are ordinary Go values, gopls autocompletes
`db.Users.` to its typed columns and their methods, and reports a wrong operand
while you type.

With multiple schemas (`schemas: [public, billing]` or `['*']`), the first
schema is the principal schema and keeps plain Go names (`Users`); every other
schema is always prefixed (`BillingUsers`), so names never change when a schema
is added (see [Configuration](docs/configuration.md#16-several-schemas)).

A first query, scanned into a row type:

```go
//qlx:row
type UserOrders struct {
    ID       int64
    Email    string
    Orders   int64
    Nickname string `qlx:"-"` // not a selected column
}

rows, err := client.All[UserOrders](ctx,
    q.Select(
        Users.ID, Users.Email, q.Count(Orders.ID).As("orders"),
    ).
        From(Users).
        LeftJoin(Orders).On(Orders.UserID.EqX(Users.ID)).
        Where(Users.Tier.Eq("pro"), Users.Nickname.IsNotNull()).
        GroupBy(Users.ID).
        Having(q.Count(Orders.ID).Gt(5)).
        OrderBy(Users.CreatedAt.Desc().NullsLast()).
        Limit(50))
```

```sql
SELECT "users"."id", "users"."email", count("orders"."id") AS "orders"
FROM "public"."users" LEFT JOIN "public"."orders" ON "orders"."user_id" = "users"."id"
WHERE "users"."tier" = $1 AND "users"."nickname" IS NOT NULL
GROUP BY "users"."id" HAVING count("orders"."id") > $2
ORDER BY "users"."created_at" DESC NULLS LAST LIMIT $3
```

There is no string-based construction: no raw fragments, no
`Where("age > ?")`. What is not modelled cannot be written until it is, and a
grammar ledger lists exactly what is missing.

The `//qlx:row` struct above needs its `ScanTargets` method: run `qlx rows ./...`
after adding or changing it (see [Mapping rows](#mapping-rows-to-go-values)).

## Examples

`client` is the connection from the Quick start. All queries return typed Go
values; a `pgx.Tx`, `*pgx.Conn` or `*pgxpool.Pool` works with the package-level
`pgxexec.One`/`All`/`Exec` too. See the [user guide](docs/GUIDE.en.md) for the
full tour.

### SELECT, filters, ordering, pagination

```go
users, err := client.All[UserRow](ctx,
    q.Select(
        Users.ID, Users.Email,
    ).
        From(Users).
        Where(Users.Tier.In("pro", "enterprise"), Users.Nickname.IsNotNull()).
        OrderBy(Users.CreatedAt.Desc()).
        Limit(20).
        Offset(40))
```

```sql
SELECT "users"."id", "users"."email" FROM "public"."users"
WHERE "users"."tier" IN ($1, $2) AND "users"."nickname" IS NOT NULL
ORDER BY "users"."created_at" DESC LIMIT $3 OFFSET $4
```

On a nullable column, a `None` in the list means NULL, so the rows that hold
NULL are matched too:

```go
users, err := client.All[UserRow](ctx,
    q.Select(
        Users.ID, Users.Email,
    ).
        From(Users).
        Where(Users.Nickname.In(qt.Some("ada"), qt.None[string]())))
```

```sql
SELECT "users"."id", "users"."email" FROM "public"."users"
WHERE "users"."nickname" = ANY($1) OR "users"."nickname" IS NULL
```

The array `$1` holds only the non-NULL values; `NotAll` does the same with
`<> ALL($1) AND "nickname" IS NOT NULL`.

To render without a database (CLI tools, migrations), use
`q.SQL(q.Dialect{Version: q.PG18}, q.Select(Users.ID).From(Users))`.

For deep pages, a keyset avoids the growing cost of `OFFSET`: `KeyAsc` /
`KeyDesc` declare the key, `KeyOrder` gives the matching `ORDER BY`, and
`.After(v)` adds the last row's value, typed like the column:

```go
byDate, byID := q.KeyDesc(Users.CreatedAt), q.KeyAsc(Users.ID)
var after q.Pred // absent on the first page
if last != nil {
    after = q.After(byDate.After(last.CreatedAt), byID.After(last.ID))
}
users, err := client.All[UserRow](ctx,
    q.Select(
        Users.ID, Users.Email,
    ).
        From(Users).
        Where(after).
        OrderBy(q.KeyOrder(byDate, byID)...).
        Limit(20))
```

When all keys go the same way, `After` renders one row comparison
`(a, b) > ($1, $2)`; mixed directions render the equivalent expansion. With no
key the predicate is absent, so the first page needs no special case.

A sort string from a URL must never reach the SQL. `NewSorts` maps names to
columns and rejects anything else with `ErrSort`:

```go
var userSorts = q.NewSorts(map[string]q.Orderable{
    "email":   Users.Email,
    "created": Users.CreatedAt,
}).Default(Users.CreatedAt.Desc()).Tiebreak(Users.ID.Asc())

order, err := userSorts.Parse(r.URL.Query().Get("sort")) // "-created,email"
if err != nil { /* 400 */ }
users, err := client.All[UserRow](ctx,
    q.Select(
        Users.ID, Users.Email,
    ).
        From(Users).
        OrderBy(order...))
```

`-` sorts descending, `+` is accepted as ascending, and the tiebreak is always
appended last.

### Joins and aggregates

```go
//qlx:row
type StatusTotals struct {
    Status  string
    Orders  int64
    Revenue qt.Null[qt.Numeric]
}

totals, err := client.All[StatusTotals](ctx,
    q.Select(
        Orders.Status,
        q.CountAll().As("orders"),
        q.SumBig(Orders.Total).As("revenue"),
    ).From(Orders).
        Join(Users).On(Orders.UserID.EqX(Users.ID)).
        GroupBy(Orders.Status).
        Having(q.CountAll().Gt(10)))
```

`qlx rows ./...` generates `ScanTargets` for `StatusTotals`; its field order
matches the `Select`, and V018 checks the names and Nullability as well.

`Join`, `LeftJoin`, `RightJoin`, `FullJoin`, `Lateral`, `OnFK` and self-joins
with aliases are all typed. A column of the optional side becomes nullable when
you wrap it with `q.Nullable`.

### Window functions

```go
byUser := q.Window().PartitionBy(Orders.UserID).OrderBy(Orders.CreatedAt.Desc())

orders, err := client.All[OrderRankRow](ctx,
    q.Select(
        Orders.ID,
        Orders.UserID,
        q.RowNumber().Over(byUser).As("nth"),
        q.Lag(Orders.Total).Over(byUser).As("previous"),
        q.SumBig(Orders.Total).Over(byUser.Rows(q.UnboundedPreceding, q.CurrentRow)).As("running"),
    ).From(Orders))
```

```sql
SELECT "orders"."id", "orders"."user_id",
       row_number() OVER (PARTITION BY "orders"."user_id" ORDER BY "orders"."created_at" DESC) AS "nth",
       lag("orders"."total") OVER (PARTITION BY "orders"."user_id" ORDER BY "orders"."created_at" DESC) AS "previous",
       sum("orders"."total") OVER (PARTITION BY "orders"."user_id" ORDER BY "orders"."created_at" DESC ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS "running"
FROM "public"."orders"
```

`q.Window()` describes the partition, order and frame (`Rows`, `Range`, `Groups`). `.Over(w)` applies it to `RowNumber`, `Rank`, `DenseRank`, `Lag`, `Lead`, `FirstValue`, `LastValue`, or any aggregate. On PostgreSQL 19, `Lag(...).IgnoreNulls()` renders `IGNORE NULLS`.

### Common Table Expressions (WITH)

```go
counts := q.NewCTE("counts",
    q.Select(Orders.UserID.As("user_id"), q.Count(Orders.ID).As("n")).
        From(Orders).
        GroupBy(Orders.UserID))

userID := q.NewField[int64]("user_id")
n := q.NewField[int64]("n")

users, err := client.All[ActiveUserRow](ctx,
    q.Select(Users.Email, q.RefNum(counts, n).As("order_count")).
        With(counts).
        From(Users).
        Join(counts).On(q.RefNum(counts, userID).EqX(Users.ID)).
        Where(q.RefNum(counts, n).Gt(5)))
```

```sql
WITH "counts" AS (
    SELECT "orders"."user_id" AS "user_id", count("orders"."id") AS "n"
    FROM "public"."orders" GROUP BY "orders"."user_id"
)
SELECT "users"."email", "counts"."n" AS "order_count"
FROM "public"."users"
JOIN "counts" ON "counts"."user_id" = "users"."id"
WHERE "counts"."n" > $1
```

`.With(cte)` attaches the CTE; its columns are read with `q.Ref`, `q.RefNum`, or `q.RefText`. CTEs support `.Materialized()`, `.NotMaterialized()`, and `q.Recursive(...)` with `.SearchDepthFirst(...)` and `.Cycle(...)`.

### Full-text search (tsvector)

Full-text search uses the typed `pgcat/fts` package and `pg` facade:

```go
import (
    "github.com/noobmaisfier/qlx/pg"
    "github.com/noobmaisfier/qlx/pgcat/fts"
)

query := pg.PlaintoTsquery("database performance")
docVec := pg.ToTsvector(Articles.Body)

articles, err := client.All[ArticleSummary](ctx,
    q.Select(
        Articles.ID,
        Articles.Title,
        pg.TsRank(docVec, query).As("rank"),
    ).
        From(Articles).
        Where(fts.OpAtAtTsvectorTsquery(docVec, query)).
        OrderBy(q.RawExpr("rank").Desc()).
        Limit(10))
```

```sql
SELECT "articles"."id", "articles"."title",
       ts_rank(to_tsvector("articles"."body"), plainto_tsquery($1)) AS "rank"
FROM "public"."articles"
WHERE to_tsvector("articles"."body") @@ plainto_tsquery($2)
ORDER BY rank DESC LIMIT $3
```

Functions include `ToTsvector`, `PlaintoTsquery`, `WebsearchToTsquery` (web-style syntax with quotes and `-`), `TsRank`, `TsHeadline`, and the `@@` match operator (`fts.OpAtAtTsvectorTsquery`).

### Vector similarity search (pgvector)

With `pgvector` enabled under `extensions:` in `qlx.yaml`, vectors are typed as `qt.Vector` (`[]float32`), with distance operators in `pgcat/ext/vector`:

```go
import "github.com/noobmaisfier/qlx/pgcat/ext/vector"

target := qt.Vector{0.05, 0.49, 0.86, /* ... */} // 1536-dim embedding

items, err := client.All[ItemMatch](ctx,
    q.Select(
        Items.ID,
        Items.Title,
        vector.OpLtEqGtVectorVector(Items.Embedding, q.Val(target)).As("cosine_distance"),
    ).
        From(Items).
        OrderBy(vector.OpLtEqGtVectorVector(Items.Embedding, q.Val(target)).Asc()).
        Limit(10))
```

```sql
SELECT "items"."id", "items"."title",
       "items"."embedding" <=> $1 AS "cosine_distance"
FROM "public"."items"
ORDER BY "items"."embedding" <=> $2 ASC LIMIT $3
```

Operators include `<=>` (cosine distance, `OpLtEqGt`), `<->` (L2 distance, `OpLtMinusGt`), and `<#>` (negative inner product, `OpLtHashGt`). `qt.HalfVector` (FP16) and `qt.SparseVector` are also supported.

### INSERT, upsert, RETURNING

```go
// One row; the generated constructor requires the columns without a default.
id, err := client.One[int64](ctx,
    q.InsertInto(Users).
        Row(Users.Email.To("ada@example.com"), Users.Tier.To("pro")).
        Returning(Users.ID))

// Several rows in one statement.
_, err = client.Exec(ctx,
    q.InsertInto(Orders).
        Row(Orders.UserID.To(1), Orders.Total.To(100), Orders.Status.To("new")).
        Row(Orders.UserID.To(2), Orders.Total.To(250), Orders.Status.To("new")))

// Upsert.
_, err = client.Exec(ctx,
    q.InsertInto(Users).
        Row(Users.Email.To("ada@example.com"), Users.Balance.To(10)).
        OnConflict(Users.Email).
        DoUpdate(Users.Balance.ToX(Users.Balance.Add(10))).
        Returning(Users.ID))
```

For many rows with `ON CONFLICT` or `RETURNING`, `InsertMany` splits them
under PostgreSQL's 65,535-parameter limit and runs the chunks in one
transaction on a pool or connection:

```go
n, err := pgxexec.InsertMany(ctx, client.Pool, client.Dialect,
    q.InsertInto(Users).OnConflict(Users.Email).DoNothing(),
    rows, pgxexec.BulkOptions{}) // rows is a []q.RowAssigner

ids, err := pgxexec.InsertManyReturning[int64](ctx, client.Pool, client.Dialect,
    q.InsertInto(Users).Returning(Users.ID), rows, pgxexec.BulkOptions{})
```

With a `pgx.Tx`, the chunks join your transaction; `MaxParams` lowers the
budget when `ToX` values carry arguments of their own. The splitting alone is
`InsertQuery.Chunks(rows, maxParams)`.

### COPY without parameters

`COPY` cannot take `$n` parameters. Without arguments the statement renders
as is (`q.CopyIn(...)` with `pgxexec.CopyIn`); with them, `.InlineArgs()`
writes the values into the SQL as literals:

```go
copyOut := q.CopyQueryOut(
    q.Select(
        Orders.ID, Orders.Total,
    ).
        From(Orders).
        Where(Orders.Status.Eq("paid"))).
    InlineArgs().With(q.WithFormat(q.CopyCSV))

st, _ := client.Render(copyOut)

// run it with pgx's own COPY plumbing:
conn := client.Pool.Acquire(ctx)
defer conn.Release()
var out bytes.Buffer
conn.Conn().PgConn().CopyTo(ctx, &out, st.SQL)
```

```sql
COPY (SELECT "orders"."id", "orders"."total" FROM "public"."orders"
WHERE "orders"."status" = 'paid') TO STDOUT (FORMAT csv)
```

Only plain values are accepted (integers, bools, floats, times, uuids, bytes,
NULL and printable-ASCII strings without quote or backslash); anything else,
including a string like `x' OR '1'='1`, is refused with `ErrParams` instead of
escaped. See [docs/GUIDE.en.md](docs/GUIDE.en.md) §9.3.

### UPDATE and DELETE

```go
_, err := client.Exec(ctx,
    q.Update(Users).
        Set(Users.Balance.ToX(Users.Balance.Sub(5)), Users.Nickname.ToNull()).
        Where(Users.ID.Eq(7)).
        Returning(Users.Balance))

_, err = client.Exec(ctx,
    q.DeleteFrom(Orders).
        Where(Orders.Status.Eq("cancelled")).
        Returning(Orders.ID))
```

`Update`/`Delete` without `Where` or `All` is rejected by the analyzer (V002),
and `All` is the explicit opt-in for a whole-table write.

### Partial updates

`To(v)` binds a value, `ToX(expr)` assigns an expression, `ToDefault()` writes
`DEFAULT`, `ToNull()` writes `NULL`, `ToIf(opt)` leaves the assignment out when
the option is unset, and `ToOrDefault(opt)` writes `DEFAULT` when the option is
unset (in an `UPDATE`, use `ToIf`: V027):

```go
q.Update(Users).
    Set(
        Users.Balance.ToX(Users.Balance.Sub(5)), // balance = balance - $1
        Users.Nickname.ToNull(),                 // nickname = NULL
        Users.Tier.ToIf(req.Tier),               // req.Tier is qt.Opt[string]; unset leaves it untouched
    ).
    Where(Users.ID.Eq(7))
```

`ToNull()` is the short form of `To(qt.None[T]())`, and also covers nullable
columns that are not a `qt.Null` (arrays, `bytea`, ranges). Go cannot reserve a
method for some column types, so it compiles on a `NOT NULL` column too: the
server answers 23502, and the analyzer reports it first (V030).

A generated patch is the same idea, collected in one struct. Only the fields
you set are written:

```go
patch := db.UserPatch{
    Nickname: qt.Of(qt.None[string]()), // set nickname to NULL
    Balance:  qt.Of(int64(90)),
}

_, err := client.Exec(ctx,
    q.Update(Users).
        SetPatch(patch).
        Where(Users.ID.Eq(7)).
        Returning(Users.Balance))
```

`SetPatch(p)` is `Set(p.Assignments()...)`; an empty patch has no `SET` and
fails with `ErrShape` instead of updating nothing.

### Dynamic filters

```go
filter := struct {
    Tier   qt.Opt[string]
    Min    qt.Opt[int64]
    Max    qt.Opt[int64]
    Search qt.Opt[string]
}{
    Tier:   qt.Of("pro"),       // present: becomes a predicate
    Search: qt.Unset[string](), // absent: no predicate at all
}

users, err := client.All[UserRow](ctx,
    q.Select(
        Users.ID, Users.Email,
    ).
        From(Users).
        Where(
            Users.Tier.EqIf(filter.Tier),
            Users.Balance.BetweenIf(filter.Min, filter.Max),
            Users.Email.ContainsFoldIf(filter.Search),
        ))
```

An `...If` predicate is a real `WHERE` predicate only when its `qt.Opt` is set.
`NeIf`, `InIf`, `IsNullIf`, `GtIf`/`GteIf`/`LtIf`/`LteIf` and `BetweenIf` cover
the other comparisons; `BetweenIf` keeps whichever bounds are set. On text,
`ContainsIf`, `ContainsFoldIf`, `HasPrefixIf`, `LikeIf` and `ILikeIf` also treat
an empty string as absent. `InIf` with a list that is set but empty matches
nothing (`FALSE`), like `In`. `q.When(opt, func(v T) Pred)` handles anything
else. Slices use one placeholder shape: `Users.ID.Any(ids)` and `...In(ids)`
render `= ANY($1)`.

Each combination of present filters is a distinct statement shape, so `n`
independent filters can produce up to `2^n` shapes: watch `ShapeCache.OnThrash`
when the list endpoint has many of them.

### Transactions and retries

```go
err := pgxexec.InTx(ctx, client.Pool, pgx.TxOptions{}, pgxexec.Retry{
    Attempts: 3,
}, func(ctx context.Context, tx pgx.Tx) error {
    if _, err := pgxexec.Exec(ctx, tx,
        q.Update(Users).
            Set(Users.Balance.ToX(Users.Balance.Sub(5))).
            Where(Users.ID.Eq(7))); err != nil {
        return err
    }
    return nil
})
```

`InTx` retries serialization failures and deadlocks; the callback must be safe
to run again. Use `pgxexec.WithSavepoint` for a partial rollback.

### Mapping rows to Go values

`client.One[R]`, `All[R]`, `Maybe[R]` and `Each[R]` accept a struct, a tuple or
a scalar. The compiler does not tie `R` to the statement, so the shape is
checked by the analyzer (V018), by `pgxexec.VerifyRow` in a test, and finally by
a test with real rows.

| `R` | Mode | Rule |
| --- | --- | --- |
| `int64`, `string`, `qt.Null[T]`, ... | scalar | exactly one column |
| `q.Tuple2`, `q.Tuple3`, ... | position | column *i* into `V`*i* |
| generated row, `//qlx:row` struct | position (`ScanTargets`) | field *i* = column *i* |
| any other struct | name | `db` tag, else lowercased field name |

A `//qlx:row` struct is the reflection-free way to name a partial result:

```go
//qlx:row
type UserSummary struct {
    ID       int64
    Email    string
    Orders   int64
    Nickname qt.Null[string] // the column is nullable
}

summaries, err := client.All[UserSummary](ctx,
    q.Select(
        Users.ID,
        Users.Email,
        q.Count(Orders.ID).As("orders"), // alias = field name
        Users.Nickname,
    ).
        From(Users).
        LeftJoin(Orders).On(Orders.UserID.EqX(Users.ID)).
        GroupBy(Users.ID))
```

Then generate `ScanTargets` in field order and run it whenever a marked struct
changes:

```bash
qlx rows ./...    # writes qlx_rows.go: one ScanTargets per //qlx:row struct
```

For `//qlx:row`, the rules that matter:

- **Position matters.** Field *i* receives column *i*. Two same-typed columns
  swapped in the `Select` read as swapped values; V018 catches it only when it
  can see the `Select`.
- **Names must match too.** Each field must be named like its column or alias
  (`Orders` for `... AS "orders"`), because V018 compares names to detect a
  permutation. A mismatch is reported, not silently accepted.
- **Use the column's Go type.** An ordinary column is `int64`, `string`,
  `time.Time`, ...; a nullable column, an aggregate or the optional side of an
  outer join is `qt.Null[T]` (`q.Nullable(Orders.Total)` types the expression
  that way). A plain `int64` fails on the first NULL.
- A computed column needs `.As("...")`; without it its name is `count`, `sum`
  or `?column?`, which no field matches.

`db` tags work for structs read by name, which is convenient for joins and
`GROUP BY` results. Generated whole-table rows already carry their types and
tags. `qlx:"-"` excludes a field from `ScanTargets`; `client.Each` streams rows.
Every path is reflection-free after the first scan plan.

Full rules, aliases, outer joins and JSON aggregation: [docs/mapping.md](docs/mapping.md).

### Errors

```go
switch {
case pgxexec.IsUnique(err, "users_email_key"):
    // HTTP 409
case pgxexec.IsForeignKey(err, ""):
    // referenced row missing
case pgxexec.IsSerialization(err):
    // retryable
case pgxexec.IsNoRows(err):
    // One found nothing
}
```

PostgreSQL error classes and constraint names survive as values; mapping them
to HTTP belongs to the application.

### Analyzer

The analyzer is the only static checker. Install it and run it:

```bash
go install github.com/noobmaisfier/qlx/analyzer/cmd/qlxvet@latest
go vet -vettool="$(go env GOPATH)/bin/qlxvet" -targets=16,17,18,19 ./...
```

It also runs in CI, gopls and golangci-lint. `qlx vet` no longer exists: the
command prints these two lines and exits 2, so an old CI step cannot pass
silently.

The analyzer reports V001–V030: a column outside `FROM`, `UPDATE` without
`WHERE`, a bare column next to `GroupBy`, an aggregate in `WHERE`, a feature
newer than your targets, `ToNull()` on a `NOT NULL` column. For mapping, V018
compares `R` with the selected
columns: count, order, field or alias names, Go types, `qt.Null` where the
column can be NULL, and the optional side of an outer join. That is what turns a
wrong struct, a missing alias or a swapped field into a `go vet` finding before
the query runs. There is one static checker and one rule set (decision D9h):
the analyzer lives in its own module so that `x/tools` stays out of the core.

A suppression needs a reason: `//qlx:ignore <reason>`. See
[analyzer/README.md](analyzer/README.md).

### Observability

```go
obs, err := otelqlx.New()
tracedDB := pgxexec.Observed(client.DB(), obs.Observe)

user, err := pgxexec.One[UserRow](ctx, tracedDB,
    q.Tagged("users.by_id", userByID))
```

Statements become OpenTelemetry spans and a duration histogram, labelled by the
`Tagged` name (or the SQL verb), never by SQL text or argument values. See
[otelqlx/README.md](otelqlx/README.md).

## How safety works

| Tier | Catches |
| --- | --- |
| **Go compiler** | wrong operand types, nullability, `LIKE` on a number, `SUM` over text, an aggregate in `WHERE`, an insert missing a required column |
| **Analyzer** (`go vet`, gopls) | a column outside `FROM`, `UPDATE` without `WHERE`, a row type that does not match the selected columns, a PostgreSQL feature newer than your targets, `ToNull()` on a `NOT NULL` column (V001–V030) |
| **Render time** | scope, grouping, shape and version rules on statements built dynamically (`ErrScope`, `ErrShape`, `ErrUnsupportedByServer`) |
| **The server** | what only PostgreSQL knows: `PREPARE` in tests (`qlx prepare`), `VerifyRow`, `VerifySchema` |

A query that compiles and passes the analyzer is accepted by PostgreSQL. That
claim is checked by differential fuzzing, and every counter-example becomes a
regression case.

## Types in custom structs

A struct field is a Go value, never a QLX builder. For a boolean column, that
means:

- `db.Users.Active` on the **query side** is a `q.BoolCol`; it builds the
  `WHERE` clause.
- In a **result struct**, the field is `bool` when the column is `NOT NULL`,
  and `qt.Null[bool]` when it can be `NULL`.

```go
// Query side: db.Users.Active is a q.BoolCol.
q.Select(Users.ID).From(Users).Where(Users.Active.Pred())

// Result side: plain Go values, with qt.Null only where NULL is possible.
type UserRow struct {
    ID     int64
    Active bool
    Nick   qt.Null[string]
}
```

The rule is: **plain Go type for a `NOT NULL` column, `qt.Null[T]` when the
column, the aggregate or the optional side of an outer join can produce
`NULL`.** `q.Col`, `q.NumCol`, `q.TextCol`, `q.BoolCol` and the other column
types are query-side types; they never appear in a result struct.

| PostgreSQL column or expression | Struct field |
| --- | --- |
| `bool` | `bool`, or `qt.Null[bool]` if nullable |
| `int2`, `int4`, `int8` | any Go integer type, or `qt.Null[T]` |
| integer key with `ids: string` | the generated ID type (`db.UserID`), or `qt.Null[db.UserID]` if nullable |
| `float4`, `float8` | `float32` or `float64`, or `qt.Null[T]` |
| `numeric` | `qt.Numeric`, or `qt.Null[qt.Numeric]` |
| `text`, `varchar`, `char(n)` | `string`, or `qt.Null[string]` |
| `bytea` | `[]byte` (`nil` is `NULL`) |
| `uuid` | `uuid.UUID`, `[16]byte` or `string`; wrap it for `NULL` |
| `date` | `qt.Date` or `time.Time`; `qt.Null[...]` if nullable |
| `timestamp` | `qt.LocalTime` or `time.Time` |
| `timestamptz` | `qt.Timestamptz` or `time.Time` |
| `time`, `timetz` | `qt.TimeOfDay`, `qt.TimeTZ` |
| `interval` | `qt.Interval` |
| `json`, `jsonb` | `qt.JSONB[T]` or `qt.RawJSON`; `qt.Null[qt.JSONB[T]]` if nullable |
| `T[]` | `[]T` (`nil` is `NULL`) |
| a range or multirange | `qt.Range[T]` (has its own `Null` flag) or `qt.Multirange[T]` (`nil` is `NULL`) |
| `hstore` | `qt.Hstore` |
| pgvector | `qt.Vector`, `qt.HalfVector` or `qt.SparseVector` |
| an enum | the generated enum type |
| geometry, network, full text, ... | the matching `qt` scalar type (`qt.Point`, `qt.Geometry`, `qt.TSVector`, `qt.MacAddr`, ...) |

`qt.Null[T]` is the general nullable wrapper: `.Valid`, `.V`, `qt.Some(v)` and
`qt.None[T]()`. `qt.Opt[T]` is **not** a result type: it is an input type for
dynamic filters (`EqIf`, `BetweenIf`, text filters) and update assignments (`ToIf`);
see [Dynamic filters](#dynamic-filters) for the full list.

For the result type itself:

- a whole-table row uses the generated struct (`db.User`);
- a partial result uses a struct marked `//qlx:row` and generated by
  `qlx rows ./...`; a tuple (`q.Tuple2` ...) is only for a throwaway two- or
  three-column query;
- a single column uses a scalar: `int64`, `string`, `qt.Null[T]`, ...
- `sql.Scanner` or a type with pgx `Scan`/`Value` methods also works as a
  field when you wrap a PostgreSQL type yourself;
- custom types mapped via `overrides:` whose Go type is a slice or map (`[]T`, `map[...]`) use `nil` for NULL and stay unwrapped, exactly like built-in arrays (`[]T`) and `bytea` (`[]byte`). Other custom overrides are wrapped in `qt.Null[T]` when nullable. See [Configuration](docs/configuration.md#13-overrides-and-json-columns).

Every `qt` scalar type is usable as a field when your column has that type; run
`go doc github.com/noobmaisfier/qlx/qt` for the complete list. Generated code
adds no new types: it uses `q.Table`, `q.*Col` on the query side and the types
above in row structs.

## Opaque IDs (opt-in)

Integer keys stay `int64` by default. Set `ids: string` in `qlx.yaml` (see [Configuration](docs/configuration.md)) to turn
ID obfuscation on:

```yaml
ids: string
```

Every single-column integer primary key, and every foreign key that points at
one, is then a typed ID. The database still stores and compares integers; only
the Go side sees the opaque string. In a result struct, use the generated ID
type directly:

```go
//qlx:row
type UserSummary struct {
    ID    db.UserID `json:"id"`
    Email string    `json:"email"`
}

// Generated by `qlx gen`:
// type UserID = qt.ID[UsersIDSpace]
// Users.ID      is qlx.Col[qt.ID[UsersIDSpace]]
// Orders.UserID is also qt.ID[UsersIDSpace]

qt.MustSetIDKey(secret) // once at startup: 16+ random bytes, stable for the data

users, err := client.All[UserSummary](ctx,
    q.Select(Users.ID, Users.Email).
        From(Users).
        Where(Users.Email.Eq("ada@example.com")))

b, _ := json.Marshal(users) // [{"id":"7mQp3VxK9cE","email":"ada@example.com"}]

id, err := qt.ParseID[db.UsersIDSpace](r.PathValue("id"))
if errors.Is(err, qt.ErrBadID) {
    // 404: malformed, forged, or an id from another table
}

user, err := client.One[UserSummary](ctx,
    q.Select(Users.ID, Users.Email).
        From(Users).
        Where(Users.ID.Eq(id)))
```

`qlx rows ./...` generates `ScanTargets` for `UserSummary`; `ID` is scanned as
the integer and converted to text only when the struct is marshalled.

The text form is always 11 characters of base58. `String`, `MarshalText`,
`UnmarshalText`, `Value` and `Scan` are implemented, so JSON, routers, `fmt`
and `slog` convert automatically. `ID.Int64()` returns the stored integer and
`qt.IDOf[db.UsersIDSpace](n)` wraps one at a boundary. Each table gets its own
derived key, so an order id cannot be used where a user id is expected, and the
compiler rejects the mistake. A primary key that is also a foreign key shares
the space of the table it references.

- Call `SetIDKey` before encoding or decoding; without a key the result is
  `qt.ErrIDKey`, never a silent fallback.
- The domain is `0 <= n < 2^48`; a larger integer is `qt.ErrIDRange`.
- Changing the key changes every string already handed out, but never the
  integers in the database. Keep it with your other long-lived secrets.
- It is obfuscation, not encryption: a valid string is not a capability, so
  keep your authorisation checks. A leaked key reveals the integers. The format
  is not compatible with Hashids or any other library.

## Performance

QLX has two modes. **Normal mode** is the default: build the statement, hash
its shape, and reuse the rendered SQL on later calls. **Static mode** renders
once with `client.Render` (or `NewStaticN`) and binds arguments per call.

On a filtered join, normal mode with a cache hit costs **5.80 µs and 22
allocations**, against 11.8 µs / 69 for a full render with no cache, 22.4 µs /
104 for squirrel and 2.91 µs / 17 for bun. Static mode costs **268 ns and 2
allocations**. Bun is faster at raw SQL construction; QLX keeps the typing and
schema checks in exchange.

Full tables, method and caveats: [bench/README.md](bench/README.md). The
allocation budgets are enforced by tests, so a regression fails the build.

## PostgreSQL coverage

QLX targets PostgreSQL **16, 17, 18 and 19**. The catalog ledger holds 3,488
functions and 805 operators; the generated package wraps 1,862 of those
functions and 793 operators with typed signatures, plus the pgvector, PostGIS,
pg_trgm, hstore, ltree and citext packs. What is not wrapped is documented in
[docs/pgcat/README.md](docs/pgcat/README.md#not-wrapped); a feature newer than
your `-targets` is caught by V009 and by the renderer.

## Known limits

- No raw SQL escape hatch, by design.
- `COPY (query)` and `COPY ... WHERE` cannot take parameters (the server refuses them): `.InlineArgs()` writes plain values as literals (integers, bools, floats, times, uuids, bytes, NULL and printable-ASCII strings without quote or backslash); anything else is refused, never escaped.
- No DDL builders; migrations stay SQL.
- PostgreSQL 19 support is verified on a release candidate.
- PostGIS wrappers follow the committed ledger; the remaining functions need a
  regenerated ledger.

See [docs/limits.md](docs/limits.md) for details.
