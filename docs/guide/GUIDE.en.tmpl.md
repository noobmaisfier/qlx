## 1. Principle

1. You write your schema in SQL (migrations); `qlx gen` reads it and generates typed Go: tables, columns, rows, inserts, patches, enums, functions.
2. You write your queries with Go builders that look like SQL; the compiler checks types and nullability, and rendering checks column scope, grouping and PostgreSQL versions.
3. No API accepts SQL text: what is not modeled cannot be written. Values are always `$n` parameters, never concatenated.

A complete example fits in a few lines:

```go
rows, err := client.All[UserRow](ctx,
    q.Select(Users.ID, Users.Email).
        From(Users).
        Where(Users.Tier.Eq("pro")).
        OrderBy(Users.CreatedAt.Desc()).
        Limit(20))
```

No `Prepare`, no cache to declare: the shape of the query is recognized on the second call (see §8).

## 2. Getting started

### 2.1 The commands

```
qlx init     # writes qlx.yaml and migrations/001_init.sql (never overwrites)
# ... write your schema in migrations/*.sql ...
qlx gen      # applies the migrations on a throwaway server, writes schema.lock + the Go package
qlx check    # fails if the generated code or schema.lock is stale or hand-edited
```

| Command | Purpose |
| --- | --- |
| `qlx init` | creates `qlx.yaml` and a first migration, never overwriting |
| `qlx gen` | generates the Go package and `schema.lock`; `-from-lock` regenerates without any database |
| `qlx check` | CI: does the generated code match the migrations? (no database) |
| `qlx verify` | CI: does a live database match `schema.lock`? |
| `qlx watch` | regenerates on every change to `migrations/` or `qlx.yaml` |
| `qlx doctor` | lists missing tools, warnings and unmanaged objects |
| `qlx vet` | static analysis (discarded builder, `UPDATE` without `WHERE`, ...) with no configuration |
| `qlx prepare` | runs `PREPARE` for every query in a `qtest.Dump` file on a real server |
| `qlx rows` | generates `ScanTargets` for your structs marked `//qlx:row` |
| `qlx sql2go` | converts SQL into qlx code (built with `-tags sql2go`) |
| `qlx regress` | translates the queries of the PostgreSQL regression suite (`-tags sql2go`) |

`qlx -config other.yaml <command>` selects another file; `.yml` and `.json` are also read.

### 2.2 An example schema

```sql
-- migrations/001_init.sql
CREATE TABLE users (
    id         bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email      text NOT NULL UNIQUE,
    nickname   text,                              -- nullable
    tier       text NOT NULL DEFAULT 'free',

    created_at timestamptz NOT NULL DEFAULT now()

CREATE TABLE orders (

    user_id bigint NOT NULL REFERENCES users (id),

    status  text NOT NULL

```

### 2.3 `qlx.yaml`, key by key

```yaml
package: db                 # generated Go package
out: db                     # output directory
schemas: [public]           # schemas read
migrations: migrations      # *.sql applied in filename order (or database_url: postgres://...)
targets: [18, 19]           # PostgreSQL versions the code must support
uuid: std                   # std = uuid.UUID, bytes = [16]byte
date: qt                    # qt = qt.Date, stdlib = time.Time
ids: int                    # string = typed opaque IDs (see §10.2)
exclude: [audit_log]        # ignored tables
overrides:                  # PostgreSQL type -> Go type
  numeric:
    type: github.com/shopspring/decimal.Decimal
    family: num
json_types:                 # json/jsonb column -> your struct
  users.settings: example.com/app/model.Settings
extensions: [pg_trgm, hstore, ltree, citext]   # typed extension packages
```

Unknown keys are errors. `targets: [16, 17, 18, 19]` is valid: a construct that is too recent for the oldest target is rejected (§11.3).

### 2.4 What is generated

For each table, for example `users`:

- a table symbol `Users` with one typed column per field: `Users.ID` (`NumCol[int64]`), `Users.Email` (`TextCol[string]`), `Users.Nickname` (`TextCol[qt.Null[string]]`), `Users.CreatedAt` (`TimeCol[time.Time]`);
- `Users.As("u")` for an alias (self-joins, correlated subqueries);
- a row struct `User` with `db:"..."` tags and `ScanTargets()` (reflection-free reads);
- an insert type: `NewUserInsert(email)` takes exactly the columns without a default value, then chained setters (`.Tier("pro")`, `.Nickname(qt.Some("ada"))`);
- a patch `UserPatch`, made of `qt.Opt`: only the fields that are set are written;
- constraints (`UsersUsersPkey`, for `ON CONFLICT ON CONSTRAINT`) and foreign keys (`Orders.FKOrdersUserIDFkey(Users)`).

Plus, for the whole schema: enums (Go type + constants), typed scalar functions and procedures, and `register.go` (schema specification for the startup check).

## 3. Connecting

```go
import (
    "example.com/qlx/pgxexec"
    q "github.com/noobmaisfier/qlx"
    "example.com/qlx/qt"
)

client, err := pgxexec.Connect(ctx, os.Getenv("DATABASE_URL"), pgxexec.ConnectOptions{
    Spec:      &db.Spec,                // checks the server version against targets
    MinServer: 18,
    OnAhead: func(server int, targets []int) {
        slog.Warn("server is newer than the generated code", "server", server, "targets", targets)
    },
})
if err != nil { return err }
defer client.Close()
```

`Connect` creates the pgx pool, registers the range codecs, detects the server version (`client.Dialect`) and prepares the shape cache. Each query is rendered for the version actually running: a construct newer than the server fails before any network call, with `ErrUnsupportedByServer`.

| `ConnectOptions` field | Purpose |
| --- | --- |
| `Mode` | pgx statement strategy (cached by default) |
| `Tracer` | observes every statement (name, fingerprint, rows, duration) |
| `AfterConnect` | your own type registrations, after the library's |
| `MinServer` | minimum major version; `Connect` fails otherwise |
| `Spec` | generated specification; compares the server version to `targets` |
| `OnAhead` | called if the server is newer than all targets |
| `Shapes` | replaces the global shape cache for this client |

`client.Pool` is the `pgxpool.Pool`; `client.DB()` is the `Querier` interface used by the package functions (`pgxexec.All(ctx, tx, ...)` also accepts a transaction).

### 3.1 Serverless and transaction-mode poolers

A function keeps its process between invocations, but four things behave
differently.

**Statement mode.** The default `CacheStatements` prepares named statements
once per connection. Behind a pooler in transaction mode (PgBouncer,
Supavisor, the Neon pooler) the server connection changes between statements,
and a scale-to-zero or a server restart drops the prepared statements. Use
`Mode: pgxexec.CacheDescribe`: it sends unnamed statements and caches their
description, the mode the package documents as safe in transaction pooling.
`pgxexec.Simple` is the last resort, for poolers that support nothing else; it
sends parameters in the text protocol, where the text form of some types
differs from the binary one.

**Pool size.** `Connect` leaves the pgxpool defaults alone, and they are sized
for a server: `pool_max_conns = max(4, NumCPU)`. A function that handles one
request at a time needs one connection per instance; a thousand concurrent
instances would otherwise open thousands. Set it in the DSN:

```text
postgres://...?pool_max_conns=1&pool_min_conns=0&pool_max_conn_idle_time=5m&statement_timeout=5s
```

**One client per process.** `Connect` runs `SHOW server_version_num`; calling it
per request throws away the pool and the shape cache. Create the client once,
at startup or lazily with `sync.Once`, and do not `Close` it at the end of a
request. After the platform freezes an instance, a pooled connection can be
dead on the next invocation: pgxpool discards it after the first failure, and
`CacheDescribe` avoids the "prepared statement does not exist" error that a
named statement cache can return after a server restart.

**Schema, migrations, ids.** Run `VerifySchema` once at cold start on the
tables the function uses, not per request (it is one catalog query), and run
migrations outside the function so concurrent instances cannot race on DDL.
When the schema uses `ids: string`, every instance must call `qt.SetIDKey` with
the same secret from the environment or a secret manager: a per-instance key
makes an id minted by one instance unreadable by another, and rotating the key
invalidates every id already handed out.

The shape cache, the pgx caches and the query registry live in the process and
are not shared between instances. The cache ceiling (32,768 shapes by default,
1,024 per shard) is not preallocated: a short statement costs about 235 bytes
once stored, so a program using a few hundred shapes pays for those only, and
the full ceiling costs roughly 8 to 15 MB. `LISTEN`/`NOTIFY` needs a connection
that stays open, so prefer polling or a queue when instances scale to zero.

### 4.10 Expressions: `CASE`, `COALESCE`, arithmetic

{{ex:case-coalesce}}

`Case[T]().When(pred, v)...Else(v)` returns a non-null result; without `Else`, `End()` returns a `qt.Null[T]`. `Coalesce` removes nullability. Others: `q.NullIf`, `q.Greatest`, `q.Least`.

{{ex:arithmetic-functions}}

Arithmetic operations are typed: `Add`, `Sub`, `Mul`, `Div`, `Mod`, `Neg`, `Abs`. Common text functions are methods (`Upper`, `Lower`, `Trim`, `Replace`, `Reverse`, `Length`...). For all other PostgreSQL functions, see §11 (`pg.Length`, `text.Concat`, ...).

### 4.11 Type conversions

{{ex:cast}}

`q.PgText`, `q.PgInt4`, `q.PgInt8`, `q.PgNumeric`, `q.PgDate`, `q.PgTimestamptz`, `q.PgJSONB`, ... are the target types. For an enum or composite type you define: `q.NewPgType[T]("schema", "name")`.

### 4.12 Row locking

{{ex:locking}}

`ForUpdate`, `ForNoKeyUpdate`, `ForShare`, `ForKeyShare`, with `Of(table...)`, `NoWait` or `SkipLocked`. This is the classic work-queue pattern: several workers each take different rows.

### 4.13 Functions that return rows

{{ex:generate-series}}

A "set-returning" function becomes a row source (`TableFunc`): you give the alias and the columns with their type (`As("s", x)`), and `q.RefNum(s, x)` reads the column. `WithOrdinality(col)` adds `WITH ORDINALITY`. `q.Unnest`, `q.Unnest2`, `q.GenerateSeries*` and the JSON functions (`JSONBArrayElements`...) are hand-written; the others are generated (§11).

### 4.14 `EXPLAIN`

{{ex:explain}}

Options: `q.Analyze`, `q.Verbose`, `q.Buffers`, `q.FormatJSON`, `q.IO` and `q.PlanAdvice` (PostgreSQL 19). `Explain` also exists on `Update`, `Delete`, `Insert` and `Merge`.

### 4.15 Naming a query

{{ex:tagged}}

The comment shows up in `pg_stat_statements` and in the server logs: a query's name becomes an observability key.

## 5. Writing

### 5.1 `INSERT`

One row, with `RETURNING`:

{{ex:insert-row}}

`To(v)` sets a value, `ToX(expr)` an expression. Several rows:

{{ex:insert-rows}}

From a `SELECT`:

{{ex:insert-select}}

A `NOT NULL` column without a default value that is left out of an `INSERT` does not render (and the analyzer reports it beforehand, V008). The generated insert type makes the omission impossible to **compile**:

```go
ins := q.InsertInto(Users).Values(
    NewUserInsert("ada@example.com").   // required columns: function parameters
        Tier("pro").                    // optional columns: setters
        Nickname(qt.Some("ada")))
```

`DefaultValues()`, `OverridingSystemValue()` and `OverridingUserValue()` cover identity columns.

Optional fields from a request body are written with `ToIf(opt)` instead of an `if` per field: an unset `qt.Opt` leaves the assignment out (the column is omitted from an `INSERT`, untouched in an `UPDATE`). `ToOrDefault(opt)` writes `DEFAULT` instead, which keeps the rows of a multi-row `INSERT` aligned; `ToDefault()` always does. Details and the rules around them are in [the DTO guide](dtos.md).

```go
q.InsertInto(Users).Row(
    Users.Email.To(r.Email),
    Users.Tier.ToIf(r.Tier), // r.Tier is a qt.Opt[string]: unset takes the column's DEFAULT
)
```

## 6. Nullability, options and patches

A nullable column is a `qt.Null[T]`: `qt.Some(v)`, `qt.None[T]()`, `.Valid`, `.V`. Pointers are not offered: a `*T` cannot tell "NULL" from "not loaded".

```go
var nick qt.Null[string]
nick = qt.Some("ada")
if nick.Valid { fmt.Println(nick.V) }
```

For a condition or a partial patch, `qt.Opt[T]` (`qt.Of(v)`, `qt.Unset[T]()`, `.Set`, `.V`) tells "leave untouched" apart from "set to NULL":

| Value | In a patch | In `EqIf` |
| --- | --- | --- |
| `qt.Unset[string]()` | field ignored | predicate absent |
| `qt.Of("x")` | `SET col = 'x'` | `col = 'x'` |
| `qt.Of(qt.None[string]())` (nullable column) | `SET col = NULL` | `col IS NOT DISTINCT FROM NULL` does not exist: use `IsNull()` |

Function results follow SQL nullability: `Coalesce(col, value)` returns a non-null type; `Scalar(sub, col)` and `Case ... End()` return a `qt.Null[T]`. "Strict" (the function returns `NULL` if an argument is) is not "non-null": `jsonb ->> 'key'` on a missing key is `NULL`, so these wrappers return `qt.Null`.

## 7. Running queries and reading results

```go
type UserRow struct {
    ID    int64  `db:"id"`
    Email string `db:"email"`
}

rows, err := client.All[UserRow](ctx, sel)          // []UserRow
one,  err := client.One[UserRow](ctx, sel)          // exactly one row, otherwise pgx.ErrNoRows / pgx.ErrTooManyRows
opt,  err := client.Maybe[UserRow](ctx, sel)        // qt.Opt[UserRow]: zero or one row
for row, err := range client.Each[UserRow](ctx, sel) { ... } // stream, without loading everything
tag,  err := client.Exec(ctx, ins)                  // no rows returned: pgconn.CommandTag
```

What `R` can be:

| `R` | Reading |
| --- | --- |
| a scalar (`int64`, `string`, `qt.Null[T]`...) | a single selected column |
| `q.Tuple1[A]` ... `q.Tuple8[...]` | columns by position, without reflection |
| a struct with `ScanTargets()` | by position, without reflection (generated structs, or `qlx rows`) |
| a struct with `db` tags | by column name, through a cached plan |

```go
// One column, a scalar
n, err := client.One[int64](ctx, q.Select(q.CountAll()).From(Users))

// Several columns without declaring a struct
t, err := client.One[q.Tuple2[int64, string]](ctx,
    q.Select(Users.ID, Users.Email).
        From(Users).
        Where(Users.ID.Eq(7)))
fmt.Println(t.V1, t.V2)
```

To have a struct of your own read without reflection, mark it and run `qlx rows`:

```go
//qlx:row
type UserSummary struct {
    ID    int64
    Email string
    Posts int64 `qlx:"-"` // ignored field: not a selected column
}
```

Fields follow the order of the selected columns. Embedded fields and generic types are rejected (the order would be a guess). A struct without `ScanTargets` is read by name, and a column with no matching field is a clear error, not a silent misread.

> The `client.All[R]` etc. methods use the generic methods of Go 1.27. The package functions `pgxexec.All[R](ctx, db, stmt)` also exist and accept a `pgx.Tx`.

### Errors

PostgreSQL errors can be tested without comparing strings:

```go
_, err := client.Exec(ctx, ins)
switch {
case pgxexec.IsUnique(err, "users_email_key"):   // 23505 on this constraint
    return ErrEmailTaken
case pgxexec.IsForeignKey(err, ""):              // 23503 (any constraint)
    return ErrUnknownUser
case pgxexec.IsNotNull(err, "email"):            // 23502 on this column
case pgxexec.IsCheck(err, ""):                   // 23514
case pgxexec.IsSerialization(err):               // 40001 or 40P01: retry (see InTx)
}
if pgxexec.IsNoRows(err) { /* One on an empty result */ }
```

### Checking the result type

The type `R` of `client.One[R]` is not tied by the compiler to the columns of the `Select`. Three safety nets, from earliest to latest:

- the analyzer (V018) compares `R` with the columns when the `Select` is written in the source: count, types, nullability, and field order for a struct with `ScanTargets`;
- `pgxexec.VerifyRow[R](ctx, conn, st)` in a test: prepares the query on a real server and checks that each column has a pgx scan plan to its destination, without running the query;
- on first execution: the by-name plan fails with "has no field for column x" or "field T.F has no column".

```go
func TestRowsMatch(t *testing.T) {
    st, _ := client.Render(userByID)
    if err := pgxexec.VerifyRow[UserRow](ctx, conn, st); err != nil { t.Fatal(err) }
}
```

None of them sees a real `NULL`: a nullable column read into a non-nullable field fails only on the row that contains the `NULL`; the analyzer flags it when the `Select` is readable, otherwise use `qt.Null[T]` or a pointer.

Query engine errors are tested with `errors.Is`: `qlx.ErrUnsupportedByServer`, `qlx.ErrShape` (malformed query: `UPDATE` without `Where`, required column left out...), `qlx.ErrInvalidIdent`.

## 8. Performance: automatic path and static statements

### 8.1 The automatic path

You have nothing to do. The first time a query *shape* goes through (same structure, different values), it is rendered and validated; after that, a hash of the shape finds the SQL and only the values are collected. About 1 to 4 µs and 11 to 32 allocations for a typical-size query, versus 7 µs and 70 for a full render.

```go
client.Shapes.Stats()   // Hits, Misses, Evictions, Size
```

To keep the number of shapes bounded: pass lists with `col.Any(slice)` (one shape for any length). Varying the structure itself is allowed and correct: a user-built report or a dynamic column set renders once per distinct shape, then reuses it. When `Evictions` keeps growing, raise the ceiling for that client (`Shapes: qlx.NewShapeCache(n)`) or render the hottest shapes once with `client.Render`.

### 8.2 Static statements

For the hottest paths, render once and bind per call (60 to 70 ns, 1 allocation):

```go
id := q.NewParam[int64]()
var userByID = q.Register("user_by_id", q.Tagged("user_by_id",
    q.Select(Users.ID, Users.Email).From(Users).Where(Users.ID.EqX(id))))

st, _ := client.Render(userByID)                          // at startup
row, err := client.One[UserRow](ctx, st, id.Bind(42))     // no AST walk
```

Typed handles avoid repeating the bindings: `pgxexec.NewStatic0..4[R](dialect, stmt, params...)` (`params` are the statement's `q.Param[T]`) gives an object with `All`, `One`, `Maybe`, `Each`, `Exec` whose arguments are typed:

```go
byID := pgxexec.NewStatic1[UserRow](
    client.Dialect,
    q.Select(Users.ID, Users.Email).From(Users).Where(Users.ID.EqX(id)),
    id)
row, err := byID.One(ctx, client.DB(), 42)   // 42 is an int64 checked at compile time
```

`Tagged` prefixes the SQL with `/* qlx: user_by_id */`. `Register` names the statement for snapshots, `qtest.Dump` and `qlx prepare`, and must be called at package level with a constant name (V003, V005).

## 9. Transactions, pipelines, COPY, LISTEN

### 9.1 Transactions with retry

```go
err := pgxexec.InTx(ctx, client.Pool, pgx.TxOptions{IsoLevel: pgx.Serializable},
    pgxexec.Retry{Attempts: 5},
    func(ctx context.Context, tx pgx.Tx) error {
        // May run several times on a serialization conflict or deadlock:
        // no side effects outside the transaction.
        // balanceStmt and debitStmt are already-rendered qlx.Stmt values (client.Render)
        bal, err := pgxexec.One[int64](ctx, tx, balanceStmt, id.Bind(7))
        if err != nil { return err }
        if bal < 100 { return ErrInsufficient }
        _, err = pgxexec.Exec(ctx, tx, debitStmt, id.Bind(7))
        return err
    })
```

`Retry{Attempts, Base, OnRetry}`: number of attempts (5 by default), first delay (10 ms, doubled with jitter), and a callback to count retries in your metrics. Only `40001` and `40P01` are retried.

### 9.2 Pipeline: several queries, one round trip

```go
// getUser and listPosts are qlx.Stmt values rendered at startup (client.Render)
var p pgxexec.Pipeline
user  := pgxexec.PipeOne[UserRow](&p, getUser, id.Bind(7))
posts := pgxexec.PipeAll[PostRow](&p, listPosts, id.Bind(7))
if err := p.Run(ctx, client.Pool); err != nil { return err }
u, _ := user.Get()     // typed; ErrNotRun before Run
ps, _ := posts.Get()
```

The types read by a pipeline need `ScanTargets` (generated structs, `qlx rows`, or `q.TupleN`). `BatchAll` / `BatchOne` read the results of a regular `pgx.Batch`, and `pgxexec.Batch` (`Queue(stmt, binds...)`, `Send`) builds one.

### 9.3 Binary `COPY`

```go
n, err := pgxexec.CopyIn(ctx, client.Pool,
    q.CopyIn(Users, Users.Email, Users.Balance),
    pgxexec.CopyRows([][]any{{"a@example.com", int64(0)}, {"b@example.com", int64(10)}}))
```

This is the fastest way to load many rows. `CopyQueryOut` and `CopyTableOut` cover `COPY ... TO`.

### 9.4 `LISTEN` / `NOTIFY`

```go
ch, _ := pgxexec.NewChannel("jobs")
for n := range pgxexec.ListenChan(ctx, client.Pool, pgxexec.ListenOptions{}, ch) {
    handle(n.Payload)
}
// sender side: client.Exec(ctx, q.Notify("jobs", "payload"))
```

The connection goes back to the pool with `UNLISTEN *`, and reconnects with an increasing delay after a disconnection. Notifications sent during the disconnection are lost: use `OnReconnect` to resynchronize.

### 9.5 Multi-tenant (RLS)

```go
st, err := client.Render(q.SetConfig("app.tenant", tenantID, true)) // tenantID: string
if err != nil { return err }
_, err = pgxexec.Exec(ctx, tx, st) // tx: the pgx.Tx of the current transaction
```

`set_config` with a **bound** value: the tenant identifier is never concatenated into the SQL.

{{ex:set-config}}

Other utility commands, rendered and run like queries: `q.Listen`, `q.Notify`, `q.SetRole`, `q.Reset`, `q.Show`, `q.DiscardPlans`, `q.SetConstraints`, `q.Savepoint`, `q.Vacuum`, `q.Truncate`, `q.LockTable`, `q.RefreshMaterializedView`, `q.Reindex`, `q.Cluster`, `q.Grant`, `q.Revoke`.

## 10. Mappings and types

Four mappings decide what you write and what you read. Understanding them avoids most runtime errors.

| Mapping | Rule in one sentence | Where |
| --- | --- | --- |
| Names: SQL schema → Go code | `snake_case` becomes `CamelCase`, with initialisms (`user_id` → `UserID`) | §10.6 |
| Types: PostgreSQL type → Go type | table below; overridden with `overrides`; an unknown type becomes `string` with a warning | table, §10.7 |
| Nullability: `NULL` → Go | nullable column = `qt.Null[T]`; optional side of a `LEFT JOIN` = you have to mark it yourself | §10.8 |
| Values: Go → SQL parameters | always a bound `$n`, never pasted text; `q.Val` adds the type | §10.9 |
| Rows: result columns → `R` | by position (`ScanTargets`), by name (`db` tags), or a scalar | §10.10 |

The table that follows is the type mapping. §10.11 explains how to check all of this before production.

| PostgreSQL | Go |
| --- | --- |
| `smallint`, `integer`, `bigint` | `int16`, `int32`, `int64` |
| `real`, `double precision` | `float32`, `float64` |
| `numeric` | `qt.Numeric` (or your own type via `overrides`) |
| `text`, `varchar`, `char(n)` | `string` |
| `"char"` (one internal byte) | `qt.Char` |
| `boolean` | `bool` |
| `bytea` | `[]byte` |
| `uuid` | `uuid.UUID` (or `[16]byte` with `uuid: bytes`) |
| `date` | `qt.Date` (or `time.Time` with `date: stdlib`) |
| `time`, `timetz` | `qt.TimeOfDay`, `qt.TimeTZ` |
| `timestamp` | `qt.LocalTime` |
| `timestamptz` | `time.Time` |
| `interval` | `qt.Interval` |
| `json`, `jsonb` | `qt.JSONB[T]` (T: `json.RawMessage` or your struct) |
| `inet`, `cidr` | `netip.Addr`, `netip.Prefix` |
| `int4range`, `daterange`, `tstzrange`... | `qt.Range[T]` |
| `int4multirange`... | `qt.Multirange[T]` |
| `T[]` | `[]T` |
| enum | generated Go type + constants |
| integer primary key with `ids: string` | `qt.ID[Space]` |
| `tsvector`, `tsquery`, `bit`, `point`, `box`, `money`, `pg_lsn`, `xml`, `regclass`, `jsonpath`... | named strings from `qt` (PostgreSQL text format) |
| nullable column of any type | `qt.Null[T]` |

A text type (`qt.TSVector`, `qt.Point`, ...) is not converted implicitly: a value of one type does not pass for another. Convert at the boundaries with the library of your choice.

### 10.1 Dates and times

```go
d := qt.DateOf(2026, time.October, 28)
d.AddDays(30).Before(qt.Today(time.UTC))
d.Time()                                  // midnight UTC, if a time.Time is needed
qt.TimeOfDayOf(13, 45, 0, 0).On(d, loc)   // combines into a time.Time
Posts.PostedOn.Gte(d)                     // a date column is compared to a qt.Date
```

`qt.Date` counts days since an epoch and supports `infinity`/`-infinity`; `qt.TimeOfDay` counts microseconds since midnight. `CURRENT_DATE` returns a `qt.Date` (`q.CurrentDate()`), `q.CurrentTime()` a `qt.TimeTZ`, `q.LocalTime()` a `qt.TimeOfDay`, `q.Now()` a `time.Time`.

### 10.2 Opaque IDs

```yaml
ids: string
```

```go
qt.MustSetIDKey(secret)   // once at startup: 16+ random bytes, stable

p, _ := client.One[blog.Post](ctx, query)
json.Marshal(p)           // {"id":"7mQp3VxK9cE","author_id":"Ck4RtYw2nHa",...}

id, err := qt.ParseID[blog.PostsIDSpace](r.PathValue("id"))   // typo or forged string: qt.ErrBadID
Posts.ID.Eq(id)           // the database always compares integers
Posts.AuthorID.Eq(id)     // does not compile: an author ID is not a post ID
```

Every single-column integer primary key, and every foreign key that references it, gets its table's ID type. Nothing changes in the database: joins, indexes and sorts stay integers. On the Go side, conversion is automatic via `encoding.TextMarshaler` (JSON, routers, `fmt`, `slog`). 11 base58 characters, fixed length, about 90 ns, no allocation.

This is obfuscation, not encryption: keep your authorization checks. Changing the key changes all the strings already handed out (never the integers). Domain: 0 to 2^48 − 1 (`qt.ErrIDRange` beyond that). See [limits](limits.md).

### 10.3 JSON

A `jsonb` column is a `qt.JSONB[T]`. With `json_types` in `qlx.yaml`, `T` is your struct:

```yaml
json_types:
  users.settings: example.com/app/model.Settings
```

```go
type Settings struct{ Theme string `json:"theme"` }
// Users.Settings is then a qt.JSONB[model.Settings] column: read and written without manual json.Unmarshal.
```

The SQL/JSON constructors have their builders: `q.JSONObject`, `q.JSONArray`, `q.JSONExists`, `q.JSONValue[T]`, `q.JSONQuery`, `q.JSONTable`, `q.JSONParse(text)` (`.WithUniqueKeys()`, PostgreSQL 17), `q.JSONSerialize`, `q.JSONScalar`. The `jsonb` operators and functions are in `pgcat/jsonb`: `jsonb.JsonbPathExists(doc, q.Val(qt.JSONPath("$.a[*] ? (@ > 1)")), vars, q.Val(true))`.

### 10.4 Arrays, ranges, enums

- Array: `Col[[]string]`; `ANY($1)` to test membership (`col.Any(slice)`); operators in `pgcat/array`.
- Ranges: `qt.Range[T]` (`Lower`, `Upper` as pointers, `LowerInc`, `UpperInc`, `Empty`); operators and bounds in `pgcat/ranges`. A null `qt.Range` carries `Null: true`.
- Enum: one Go type per enum with its constants, comparable and typed (`Members.Tier.Eq(TierPro)`).

### 10.5 `numeric`

`qt.Numeric` keeps the exact value as text. For a decimal library, declare the override:

```yaml
overrides:
  numeric:
    type: github.com/shopspring/decimal.Decimal
    family: num
```

### 10.6 Names

The generator turns SQL names into exported Go identifiers:

| SQL | Go | Rule |
| --- | --- | --- |
| `user_id` | `UserID` | words separated by `_`, first letter capitalized, initialisms in uppercase |
| `api_url` | `APIURL` | recognized initialisms: `id url uuid api ip http https json jsonb html sql xml uri ttl cpu os db tls ssl ssh csv pdf ui` |
| table `users` | `Users` (symbol), `UsersT` (type), `User` (row) | the row is the singular: `ies` → `y`, `sses/xes/ches/shes` → without `es`, `ss/us/is` unchanged, otherwise without the final `s` |
| column `type` | `Type` | a reserved package word gets the suffix `Col`; two columns that give the same name are numbered |
| colliding table | schema suffix, then `Row` or a number | so that two schemas do not overwrite the same symbol |

The row struct keeps the SQL name in its tags: `ID int64 `db:"id"``, `UserID int64 `db:"user_id"``. That tag is what drives reading by name (§10.10), not the Go name.

### 10.7 Types: how a type is chosen

For each column, the generator tries in this order:

1. an `override` for `schema.type`, then for `type`;
2. an array → `[]T` with the element type;
3. a domain → the type of its base;
4. an enum → the generated Go type;
5. a range or multirange → `qt.Range[T]` / `qt.Multirange[T]`;
6. a native type from the table above;
7. a type from an enabled extension (`extensions:` in `qlx.yaml`);
8. otherwise `string`, with a warning at generation: "add an override or enable its extension pack". This is the case for a composite type or a type from an extension that is not enabled.

```yaml
overrides:
  numeric:                       # all numeric columns
    type: github.com/shopspring/decimal.Decimal
    family: num
  billing.money_amount:          # a single type, by schema.name
    type: example.com/app/money.Amount
    family: num
```

`family` chooses the column's operators: `num` (`Gt`, `Add`, `Sum`...), `text` (`Like`, `Upper`...), `time` (date comparisons), otherwise `col` (equality, `IN`, `IS NULL`). A type you bring must know how to read and write itself with pgx (`Scan`/`Value` or the `pgtype` interfaces).

A few clarifications:

- `varchar(n)` and `char(n)` are `string`: the length is not checked on the Go side, the database checks it on write.
- No unsigned types: `oid` is the only `uint32`.
- `json` and `jsonb` are the same Go types (`qt.JSONB[T]`); `json_types:` chooses `T` per column (§10.3).
- `date: stdlib` gives `time.Time` instead of `qt.Date`; `uuid: bytes` gives `[16]byte`.

### 10.8 Nullability

A `NOT NULL` column is a `T`. A nullable column is a `qt.Null[T]` (`.Valid`, `.V`, `qt.Some`, `qt.None[T]()`, JSON: `null` or the value). Three types already carry their own "absence" and are not wrapped: an array (`[]T`, `nil` = `NULL`), `bytea` (`[]byte`, `nil` = `NULL`) and a range (`qt.Range` has a `Null` flag).

What the database or the expression decides:

| Expression | Go type |
| --- | --- |
| `NOT NULL` column | `T` |
| `Count`, `CountAll` | `int64` |
| `Sum`, `Avg`, `Max`, `Min`, `ArrayAgg`... | `qt.Null[T]` (no rows = `NULL`) |
| `Coalesce(col, value)` | `T` |
| `Scalar(subquery, col)`, `Case ... End()` | `qt.Null[T]` |
| "strict" function on a null argument | `qt.Null[T]` when the result can be `NULL` |

**The outer join trap.** The columns on the optional side of a `LEFT JOIN` (the joined table), of a `RIGHT JOIN` (the other table) or on both sides of a `FULL JOIN` are `NOT NULL` in the schema, so they are typed `T`, but they are `NULL` when no row matches. Read into an `int64`, they make reading that row fail (`cannot scan NULL into *int64`), and only when the case occurs. Two correct ways:

{{ex:left-join-nullable}}

`q.Nullable(col)` does not change the SQL: it types the value as `qt.Null[T]`, so the field that receives it must be a `qt.Null[T]` (or a pointer). You can also read the raw column into a `qt.Null[T]` field: reading a `T` into a `qt.Null[T]` is always allowed. The analyzer (V018) flags an optional-side column read into a field that cannot hold `NULL`.

In the other direction, writing: `qt.None[T]()` gives `NULL`, `qt.Some(v)` gives the value; for a partial patch, `qt.Opt[T]` distinguishes "do not touch" from "set to `NULL`" (§6).

### 10.9 Go values → parameters

A Go value is never written into the SQL: it becomes a `$n` parameter that pgx encodes. The accepted types are those of the columns (§10) plus anything pgx knows how to encode.

- `Users.Balance.Gt(100)`: `100` is an `int64` checked by the compiler (the column's type), rendered `$3` without a cast: the server infers the type of the comparison.
- `q.Val(x)`: the parameter carries its type, rendered `$1::int8`, `$2::text`. Necessary when the server has nothing to infer it from (a lone value in a `SELECT`, an argument of a polymorphic function):

{{ex:param-typing}}

- `q.NewParam[T]()`: named parameter, bound at each execution with `.Bind(v)` (§8.2).
- `col.Any(slice)`: a single array parameter for any length (§4.2).
- `qt.Null` and `qt.Opt` are written as described in §6; a `qt.Range` carries its bounds and its empty flag.
- A value of a `qt` text type (`qt.Point`, `qt.TSVector`...) is sent in PostgreSQL's text format; `qt.JSONB[T]` is serialized as JSON.

Identifiers (table, column and constraint names) are never parameters: they come from the generated code; a hand-written name is validated and quoted (`q.QuoteIdent`, `ErrInvalidIdent`).

### 10.10 Result columns → `R`

This section is the summary; [Mapping rows to Go types](mapping.md) has every case (joins, nested data, tuples) and how each mapping is checked.

`client.One[R]` reads each row into `R` using one of three modes, chosen in this order:

| Mode | When | Matching rule |
| --- | --- | --- |
| Position | `*R` has a `ScanTargets()` method: generated structs, `qlx rows`, `q.Tuple1..8` | column *i* goes into field *i* of the list; same number of columns and fields |
| Name | `R` is a struct without `ScanTargets` | the column name (lowercased) is compared to the `db` tag, otherwise to the **lowercased** field name |
| Scalar | `R` is not a struct, or is a struct that is a value (`time.Time`, `qt.Null[T]`, `netip.Addr`) read from a single column | exactly one column |

The rules of reading by name that surprise people the most:

- The Go name is **not** converted to `snake_case`: a field `UserID` is called `userid`, not `user_id`. For a `user_id` column, write `UserID int64 `db:"user_id"``. Generated structs already carry the tags.
- A column without a field is an error: `T has no field for column x (tag a field with db:"x")`. So is a field without a column: `field T.F has no column in the result (tag it db:"-" to skip it)`. There is no silently ignored column and no field silently left at zero. Two result columns with the same name (`users.id` and `orders.id` in a join) are an error as well: alias one with `.As("order_id")`.
- Unexported fields are ignored; `db:"-"` ignores an exported field; an embedded anonymous struct without a tag has its fields flattened.
- A computed column without an alias has the name PostgreSQL gives it (`count`, `sum`, `coalesce`, `?column?`): always give it an alias with `.As("total")` when it goes into a struct.
- The by-name plan is computed once per (type, column list) and then cached.

Reading by position, with a struct of your own:

```go
//qlx:row
type UserSummary struct {
    ID    int64
    Email string
    Posts int64
}

sel := q.Select(Users.ID, Users.Email, q.Count(Posts.ID).As("posts")).
    From(Users).LeftJoin(Posts).On(Posts.AuthorID.EqX(Users.ID)).GroupBy(Users.ID)
rows, err := client.All[UserSummary](ctx, sel)
```

After `qlx rows`, `UserSummary` has a `ScanTargets` method that follows the **field order**: the order of the `Select` must be the same. Two columns of the same type swapped produce no error, only swapped values: the analyzer detects this by comparing names (V018).

What pgx can read into a field (checked on PostgreSQL 16 with `VerifyRow`):

| Column | Accepted fields | Rejected |
| --- | --- | --- |
| `int2`, `int4`, `int8` | any integer, `float64`, `string` (rendered as text); `qt.Null[...]` or pointer if nullable | `bool` |
| `float4`, `float8` | `float64`, `float32`; an integer is accepted but fails if the value is not whole | |
| `numeric` | `qt.Numeric`, `float64`, or your override type | |
| `text`, `varchar` | `string`, `[]byte` | a number |
| `bool` | `bool` | an integer |
| `timestamptz`, `timestamp`, `date` | `time.Time`, the matching `qt` types | `string` |
| `bytea` | `[]byte` | |
| `T[]` | `[]T` | a scalar |
| `uuid` | `uuid.UUID`, `[16]byte`, `string` | |
| `jsonb` | `qt.JSONB[T]`, `[]byte`, `string` | |
| enum | the generated Go type | |

A read plan that exists does not rule out a value error: an `int8` too large for an `int16`, a non-integer `float8` into an `int64`, a `NULL` in a field that cannot hold it. This is what the analyzer and `VerifyRow` cannot decide.

### 10.11 Checking the mappings

From earliest to latest:

| Check | Sees | Does not see |
| --- | --- | --- |
| compiler | nonexistent columns, operand types, `T` versus `qt.Null[T]` in expressions | the `R` type of `client.One[R]`: it is not tied to the `Select` |
| `qlx gen` / `qlx check` | schema and generated code out of sync | |
| analyzer V018 | `R` against the columns of a `Select` written in the source: count, names, Go types, possible `NULL` (including the optional side of an outer join), order | statements built in functions or loops |
| `pgxexec.VerifyRow[R]` in a test | any statement, on a real server, without running it: count, names, pgx read plan of each column | an actual `NULL` |
| `pgxexec.VerifySchema` at startup | the real schema against the generated code | |
| a test with real rows, including one with `NULL` | what nothing else sees | |

A practical rule: for each registered query, a test that calls `VerifyRow` with the production result type, plus a dataset that contains at least one row with `NULL` in every nullable or optional column.

## 11. PostgreSQL functions and operators

Every function and operator in the catalog is a typed wrapper, generated from the server catalog (`pgcat.json`, PG 16 to 19):

```go
import "example.com/qlx/pg"                 // flat facade: pg.Lower, pg.Concat, ...
import "example.com/qlx/pgcat/num"           // or by domain: text, num, array, datetime, jsonb, fts, geo, network, ranges, binary, xml, sys, misc

q.Select(pg.Lower(Users.Email)).From(Users)
q.Select(num.StddevInt8(Orders.Total).
        Filter(Orders.Status.Eq("paid"))).
    From(Orders) // typed aggregate + FILTER
```

### 11.1 How wrappers are typed

| Case | Go form |
| --- | --- |
| Ordinary function | `Lower(a Operand[string]) Expr[string]` |
| Result that can be NULL | `Expr[qt.Null[T]]` (NULL input for a non-strict function; `lower(range)`, `->>`, `regexp_match`... for the cases where the catalog says "strict" but the result can still be NULL) |
| Variadic | `Concat(rest ...qlx.Value)` ; `FormatTextAny(fmt, rest ...qlx.Value)` |
| `void` return | `Expr[qt.Void]` (advisory locks, `pg_notify`...) |
| Polymorphic types | generics: `Operand[E]`, `qt.Range[E]`, `qt.Multirange[E]` |
| Aggregate | `AggExpr[R]`: accepts `Filter`, `Distinct`, `OrderBy`, `Over`; NULL on zero rows except `count`/`regr_count` |
| Scalar set-returning function | `qlx.TableFunc`: `num.GenerateSeriesInt4Int4(a, b).As("s", x)` then `q.RefNum(s, x)`; the column type is that of the `Field` you declare |
| Function with `OUT` / `TABLE` columns | `TableFunc` + typed columns (all nullable; `catcode` is a `qt.Char`): `cols := sys.PgGetKeywordsCols` ; `e := sys.PgGetKeywords().As("e", cols.Fields()...)` ; `q.Ref(e, cols.Word)` |
| Function added in PG N | render error naming the version if the target is older |

Function whose record changes between major versions (`pg_stat_get_wal`, `pg_get_replication_slots`...): one wrapper per shape, named by its versions (`PgStatGetWalUpTo17`, `PgStatGetWalV18`, `PgStatGetWalFrom19`); the unsuffixed name no longer exists, use the versioned name.

Name collisions between types (text `Lower` versus interval `Lower`): the name stays plain in the main domain; the others get a type suffix (`BitAndInt4`, `StddevFloat8`). Variants with nullable arguments end in `N` (`LowerN`).

Examples of wrappers of different shapes:

```go
text.Concat(Users.Email, q.Val("-x"))                              // variadic: Expr[qt.Null[string]]
sys.PgAdvisoryLockInt8(q.Val(int64(42)))                            // void: Expr[qt.Void]
fts.SetweightTsvectorChar(vec, q.Val(qt.Char('A')))                // "char" type
jsonb.JsonbPathExists(doc, q.Val(qt.JSONPath("$.a")), vars, q.Val(true))
```

Written by hand in the main package, because they have a shape of their own: `Count`/`CountAll`, `Sum`, `Avg`, `Min`, `Max`, `StringAgg`, `ArrayAgg`, ordered-set aggregates (`PercentileCont`, `PercentileDisc`, `Mode`), the 15 window functions, `Coalesce`, `Case`, `Cast`, SQL/JSON constructors, XML (`XMLElement`, `XMLTable`...), `CurrentDate/Time/Timestamp`, `LocalTime`, `Unnest`, `GenerateSeries`.

Not generated: functions of type `internal`/`cstring`/`trigger` (reserved for the server), type input/output functions, operator implementations (use the operator), rare statistics types (`pg_ddl_command`, BRIN summaries). A missing function is reported; it is not worked around with raw SQL (§15).

Extensions: `pgcat/ext/hstore`, `ltree`, `citext`, `pgtrgm` (enable them in `extensions:` to get the column types too). For pgvector and PostGIS: `pgcat extract -ext pgvector` on a real server produces the ledger, `pgcat gen` the wrapper.

### 11.2 Operators

Operators are wrappers like functions (`text.` for `||`, `jsonb.` for `->`, `array.` for `@>`, `network.` for `<<`...). The [reference](pgcat/) lists each form with its version range and its volatility.

### 11.3 PostgreSQL versions

A construct newer than your oldest target is a render error that names the version (`IGNORE NULLS` in PG 19, `RETURNING OLD/NEW` in PG 18, `JSON_SERIALIZE` in PG 17...). The error wraps `qlx.ErrUnsupportedByServer`. With `targets: [18, 19]`, whatever is 19-only is rejected at build time by the analyzer (V009) and at render time on an 18 server.

### 12.1 Who catches what

| Real `PREPARE` | everything only the server knows: `qtest.Dump` then `qlx prepare -queries queries.json` |

Analyzer codes (`go vet -vettool`, gopls, golangci-lint). Rule: an error *present* in the code (column assigned twice) is always reported; a *missing* part (no `Set`) is reported only when the chain is passed on as is (argument, composite literal, or a `return` whose result is `qlx.Statement`); a chain held in a variable or returned as a builder (`SelectQuery`, `TableFunc`...) may be completed later. An argument the analyzer cannot resolve (`args...`, helper function) makes it silent, never approximate:

| Code | Reports |
| --- | --- |
| V001 | result of a builder discarded (builders are immutable) |
| V002 | `Update`/`Delete` passed on without `Where` or `All` |
| V003 | `Register` name that is not constant or is duplicated |
| V004 | result or error of `SQL`/`Render` ignored |
| V005 | `Register` inside a function body |
| V006 | column of a table absent from `FROM`/`JOIN`/`USING` |
| V007 | aggregate mixed with bare columns without `GroupBy` |
| V008 | `INSERT` that does not set all the required columns |
| V009 | `EXPLAIN` function, method or option whose version range does not cover `-targets` |
| V010 | `//qlx:ignore` without a reason |
| V012 | required part missing: `UPDATE` without `Set`, `INSERT` without a row, `MERGE` without `Using`/`On`/`When`, `DoUpdate` without an assignment, `CASE` without `When`, empty `Truncate()`... |
| V013 | contradictory or duplicated parts: column assigned twice, `Limit` with `FetchFirst`, `WithTies` without `FetchFirst`/`OrderBy`, rows with different columns, `INSERT ... SELECT` or union operands of different widths |
| V014 | column selected next to a `GroupBy` that does not mention its table |
| V015 | `EXPLAIN` option that requires `Analyze` (`Wal`, `IO`, `SerializeText`...) or excludes it (`GenericPlan`) |
| V016 | `ForUpdate().Of(t)` with a table absent from `FROM`/`JOIN` |
| V017 | `SearchDepthFirst`/`SearchBreadthFirst`/`Cycle` on a non-recursive CTE |
| V018 | result type that does not match the `Select`: number of columns, field names, Go types, `NULL` in a non-nullable field, field order |
| V019 | window function in `Where`, `Having`, `On` or `GroupBy` (PostgreSQL forbids it: filter in a subquery or a CTE) |
| V020 | named window used by `Over(w.Spec())` / `w.Extend()` but absent from the query's `Windows(...)` |
| V021 | `Func` without `As`, `JSONTable`/`XMLTable` without a column or with an empty alias |
| V022 | `$x` variable of a JSON path not passed through `Passing(Pass("x", ...))`, or `KeepQuotes`/`OmitQuotes` with a `WITH WRAPPER` |
| V023 | `Grant`/`Revoke`: missing privilege, `OnTables`, roles; `To`/`From` swapped; `WithGrantOption` on REVOKE, `Cascade` on GRANT |
| V024 | `Refresh...Concurrently()` with `WithNoData()`; `SetConstraints` without a name |
| V025 | `SearchOrder()` / `CycleMark()` on a CTE built without `SearchDepthFirst`/`SearchBreadthFirst` / `Cycle` |
| V026 | conflict column or assignment (`Set`, `Row`, `DoUpdate`) that designates a column of a table other than the one written |
| V027 | `ToOrDefault` in a `SET` list (`Set`, `DoUpdate`, `ThenUpdate`): an absent field would reset the column to its default, `ToIf` leaves it alone |

An accepted finding is suppressed with a comment on the same line or the previous one: `//qlx:ignore <reason>`. With `-audit`, each suppression is itself listed (V011).

### 12.2 Testing your queries

Without a database, render and compare to a reference file ("golden"):

```go
func TestUsersByTier(t *testing.T) {
    sql, args, err := q.SQL(q.Dialect{Version: q.PG18}, usersByTier("pro"))
    if err != nil { t.Fatal(err) }
    if sql != `SELECT "users"."id" FROM "public"."users" WHERE "users"."tier" = $1` || args[0] != "pro" {
        t.Fatalf("got %s %v", sql, args)
    }
}
```

With a server: `scripts/with_pg.sh go test ./...` starts a throwaway cluster; `qtest.Dump(t, dialect, "queries.json")` writes all the `Register`ed queries, and `qlx prepare -queries queries.json` asks your CI database to `PREPARE` them: a column renamed in production fails in CI, not at 3 a.m.

`pgxexec.VerifySchema(ctx, db, spec, "users", "orders")` compares at startup only the tables the program uses.

## 13. Recipes

### 13.1 Cursor pagination (keyset)

```go
func nextPage(afterID int64, size int64) q.Statement {
    return q.Select(Orders.ID, Orders.Total).From(Orders).
        Where(Orders.ID.Gt(afterID)).
        OrderBy(Orders.ID.Asc()).
        Limit(size)
}
```

Unlike `Offset`, the cost does not grow with depth, and the shape is the same for every page.

### 13.2 Atomic counter

{{ex:upsert}}

An upsert with `Excluded()` or an expression on the existing column avoids "read then write" and its conflicts.

### 13.3 Work queue

See the `FOR UPDATE SKIP LOCKED` locking (§4.12), inside a transaction: select the batch, process it, mark it done, commit.

### 13.4 Loading many rows

Fewer than 1,000 rows: a multi-row `INSERT` (§5.1). Beyond that: `pgxexec.CopyIn` (§9.3).

### 13.5 Search with optional filters

```go
func search(email string, tier qt.Opt[string], minBalance qt.Opt[int64]) q.Statement {
    sel := q.Select(Users.ID, Users.Email).From(Users)
    if email != "" {
        sel = sel.Where(Users.Email.ILike("%" + email + "%"))
    }
    return sel.Where(Users.Tier.EqIf(tier), Users.Balance.EqIf(minBalance)).OrderBy(Users.ID.Asc()).Limit(50)
}
```

Each combination of present filters is one shape, rendered only once.

### 13.6 Soft delete

A `deleted_at timestamptz` field: `Update(...).Set(T.DeletedAt.ToX(q.Now()))` in place of `Delete`, and `Where(T.DeletedAt.IsNull())` in your read queries (put it in a shared `alive()` function).

## 15. What does not exist (on purpose)

- No raw SQL: `Raw(...)` does not exist. A form that is not modeled is reported (grammar ledger) and added instead of being worked around.
- No DDL: the schema lives in your SQL migrations.
- No pointers for NULL: `qt.Null[T]`.
- No constructs the server rejects: `XMLTABLE` with a namespace `DEFAULT`, `XMLSERIALIZE ... bytea`, etc. have no builder.
- `In` with a nullable element, parameterized `COPY (query)`: see [limits](limits.md).

## 16. Troubleshooting

| Message | Cause | Fix |
| --- | --- | --- |
| `qlx check` fails | generated code or `schema.lock` modified/stale | `qlx gen` |
| `ErrUnsupportedByServer` | construct newer than the target or the server | avoid its use, or raise `targets` |
| `ErrShape` "UPDATE has no WHERE" | `Update`/`Delete` without a condition | `Where(...)` or `All()` |
| `ErrShape` required column | `INSERT` without a `NOT NULL` column that has no default | set it; use `NewXInsert` |
| `qt.ErrIDKey` | `SetIDKey` not called | `qt.MustSetIDKey` at startup |
| `qt.ErrBadID` | ID text is wrong or belongs to another table | reject the request (400) |
| `qt.ErrIDRange` | integer outside 0..2^48−1 | does not happen with a normal identity |
| `pgx.ErrTooManyRows` / `ErrNoRows` | `One` on several rows or zero | `Maybe` or `All` |
| shape cache `Evictions` rising | unbounded shapes | `col.Any(slice)`, no dynamic columns |
| "cannot scan ... into *qt.X" | text type without `Scan` | use the intended `qt` type (all the types in §10 have one) |
| missing `go.sum` | unresolved dependencies | `go mod tidy` |
| V006 / V007 / V008 | column out of scope, aggregate without `GroupBy`, incomplete `INSERT` | fix the query |
