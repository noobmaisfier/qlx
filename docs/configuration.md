# Configuration

Everything you can configure in QLX, in one place. There are five layers, from
build time to run time:

| Layer | Where | What it controls |
|---|---|---|
| [`qlx.yaml`](#1-qlxyaml-the-generator) | a file in your repository | what `qlx gen` generates, and from which schema source |
| [`qlx` commands](#2-the-qlx-command) | flags and environment | which config file, which database, which server binaries |
| [Runtime options](#3-runtime-options) | Go code | dialect, pool mode, retries, caches, listening, bulk inserts, telemetry |
| [The analyzer](#4-the-analyzer-qlxvet) | `qlxvet` flags and comments | which PostgreSQL versions the code must support, ignore rules |
| [Environment variables](#5-environment-variables) | process environment | connection strings, test and CI settings |

Defaults are listed next to every option. An option you do not set keeps its
default, and the default is the safe one.

---

## 1. `qlx.yaml` (the generator)

### 1.1 Finding and reading the file

`qlx` looks in the current directory for `qlx.yaml`, then `qlx.yml`, then
`qlx.json`, and uses the first it finds. Pass `-config path/to/file` to use
another one. All three formats have the same keys.

- **Unknown keys are errors.** A typo such as `target:` for `targets:` stops
  the command instead of being ignored.
- **Paths are relative to the config file**, not to where you run the command:
  `migrations`, `out` and `lock` are resolved against the file's directory.
  Absolute paths are used as they are.
- **YAML is a small subset**: nested mappings by indentation, block lists
  (`- a`), inline lists (`[a, b]`), quoted and plain scalars, and `#` comments.
  Anchors, several documents in one file, block scalars (`|` and `>`) and
  inline mappings (`{a: 1}`) are rejected with an error rather than guessed at.
  Tabs cannot indent. If you need more than this, use `qlx.json`.
- `qlx init` writes a starting `qlx.yaml` and a `migrations/` directory. It
  never overwrites an existing config.

### 1.2 Reference

| Key | Type | Default | Meaning |
|---|---|---|---|
| `package` | string | `db` | Go package name of the generated code. |
| `out` | path | the package name | Directory the package is written to. Files that carry the `// Code generated by qlx; DO NOT EDIT.` header and no longer correspond to a table or type are removed; other files are never touched. |
| `schemas` | list of strings | `[public]` | PostgreSQL schemas to generate for. |
| `lock` | path | `schema.lock` | The sealed copy of the schema that `gen`, `check`, `verify` and `doctor` work from. Commit it. |
| `migrations` | path | none | A directory of `*.sql` files, applied in name order to a throwaway server. One of the two schema sources. |
| `database_url` | string | none | A live server to read the schema from. The other schema source. Wins over `migrations` when both are set. |
| `pg_bin` | path | auto | Directory with `postgres`, `initdb` and `pg_ctl`, for `migrations`. See [§2.3](#23-finding-the-postgresql-binaries). |
| `targets` | list of integers | `[18, 19]` | PostgreSQL majors the code must run on, each between 14 and 99. Written into the generated package, where the runtime and the analyzer read it. |
| `exclude` | list of strings | none | Tables to leave out, as `schema.table` or `table`. |
| `extensions` | list of strings | none | Extension packs to generate typed support for. See [§1.4](#14-extension-packs). |
| `overrides` | mapping | none | Go type for a PostgreSQL type. See [§1.3](#13-overrides-and-json-columns). |
| `json_types` | mapping | none | Go document type of a `json`/`jsonb` column. See [§1.3](#13-overrides-and-json-columns). |
| `uuid` | `std` \| `bytes` | `std` | `std` is the standard library's `uuid.UUID` (Go 1.27); `bytes` is `[16]byte`, for code that must still build on an older toolchain. |
| `date` | `qt` \| `stdlib` | `qt` | `qt` is `qt.Date`, a calendar date with no time zone; `stdlib` is `time.Time` at midnight UTC. |
| `timestamptz` | `qt` \| `stdlib` | `stdlib` | `stdlib` is `time.Time`, which cannot hold `infinity` (reading such a row fails). `qt` is `qt.Timestamptz`, which can, and also reads and writes `-infinity`. |
| `array_nulls` | bool | `false` | `true` types every array element as `qt.Null[T]`, so a `NULL` element can be read. PostgreSQL never says whether an array may hold NULLs, so with the default (`[]T`) the row that holds one fails to read. Costs a wrapper per element. |
| `ids` | `int` \| `string` | `int` | `string` types every single-column integer primary key, and every foreign key pointing at one, as the table's `qt.ID`: an opaque 11-character string in JSON and URLs. The database columns do not change. See [§1.5](#15-opaque-ids). |
| `nullable` | `null` | `null` | How nullable columns appear: `qt.Null[T]`. No other value is accepted: a `*T` cannot tell NULL from "not loaded", which is what `Null[T]` exists to prevent. |

Validation happens when the file is read, and the message names the key:

```
qlx.yaml: uuid must be "std" or "bytes", not "uuid"
qlx.yaml: targets lists PostgreSQL majors such as 18 and 19, not 8
qlx.yaml: unknown extension pack "postgres" (known: btree_gist, citext, ...)
```

### 1.3 Overrides and JSON columns

`overrides` changes the Go type of a PostgreSQL type. The key is a bare type
name (`numeric`, every such column) or `schema.type` (one type); the schema form
is looked up first.

```yaml
overrides:
  numeric:                       # all numeric columns
    type: github.com/shopspring/decimal.Decimal
    family: num
  billing.money_amount:          # a single type, by schema.name
    type: example.com/app/money.Amount
    family: num
  tags:
    type: "[]string"             # a slice or map stays unwrapped (nil is NULL)
```

- `type` is a Go type expression, `import/path.Name` for a type from another package.
- `family` chooses the column's operators: `num` (`Gt`, `Add`, `Sum`...), `text`
  (`Like`, `Upper`...), `time` (date comparisons), otherwise `col` (equality,
  `IN`, `IS NULL`).
- A type you bring must read and write itself with pgx (`Scan`/`Value`, or the
  `pgtype` interfaces).
- A nullable column of an overridden type is `qt.Null[T]`, except when `type`
  starts with `[]` or `map[`: those are already nil-able and stay as they are,
  like the built-in arrays.

`json_types` gives a `json` or `jsonb` column a document type. The key is
`table.column` (or `schema.table.column`), the value a Go type:

```yaml
json_types:
  users.settings: example.com/app/model.Settings
```

The column becomes `qt.JSONB[Settings]` and reads and writes that type
directly. Columns not listed stay `qt.JSONB[json.RawMessage]`.

### 1.4 Extension packs

`extensions` turns on typed support (column types, functions, operators) for an
extension that is installed in your database. The known packs are:

`pgvector`, `postgis`, `pg_trgm`, `hstore`, `ltree`, `citext`, `pgcrypto`,
`uuid-ossp`, `unaccent`, `fuzzystrmatch`, `btree_gist`.

A type from an extension that is not enabled becomes `string` with a warning
at generation time. Enabling a pack does not create the extension in your
database: that is your migration's `CREATE EXTENSION`.

### 1.5 Opaque IDs

With `ids: string`, the text form of an ID is derived from a secret. Set it
once at program start, before any ID is encoded or decoded:

```go
if err := qt.SetIDKey(secret); err != nil { // at least 16 bytes
    log.Fatal(err)
}
```

Keep the secret as stable as the data: changing it changes every text form ever
handed out (links, API clients, stored strings), though never the integers in
the database. Calling `SetIDKey` again replaces the key; do that only in tests.

### 1.6 Where the schema comes from

`gen` needs one source, tried in this order:

1. `database_url`, a live server (its catalogs are read);
2. `migrations`, applied to a **throwaway server** that `qlx` starts and
   removes itself (the PostgreSQL server binaries must be installed; see
   [§2.3](#23-finding-the-postgresql-binaries));
3. `-from-lock`, which regenerates from the committed `schema.lock` and touches
   no server at all.

`check` reads only `schema.lock`. `doctor`, `verify` and `prepare` also look at
the schema source or a live database (see the table in §2.1).

### 1.7 A complete example

```yaml
package: db
out: internal/db
schemas: [public, billing]
migrations: migrations
targets: [16, 17, 18, 19]
exclude: [public.schema_migrations]
extensions: [pg_trgm, citext]
uuid: std
date: qt
timestamptz: qt
ids: string
json_types:
  users.settings: example.com/app/model.Settings
overrides:
  numeric:
    type: github.com/shopspring/decimal.Decimal
    family: num
```

## 2. The `qlx` command

```
qlx init | gen | check | verify | doctor | watch | prepare | rows | sql2go | regress  [flags]
```

### 2.1 What each command reads

| Command | Config file | Reads | Notes |
|---|---|---|---|
| `init` | no | writes `qlx.yaml`, `migrations/001_init.sql` | `-package` (default `db`), `-out` (default: the package), `-dir` (default `.`). Refuses to overwrite. |
| `gen` | yes | `database_url`, else `migrations`, else `schema.lock` with `-from-lock` | Writes `schema.lock` and the package; only changed files are rewritten. |
| `check` | yes | `schema.lock` | Regenerates in memory and compares bytes with the package on disk. Use it in CI. |
| `verify` | yes | `schema.lock` and a live database | Fails if the database differs from the lock. The URL is `$DATABASE_URL`, else `database_url`. |
| `doctor` | yes | `schema.lock`, and the schema source | Prints `ok` / `FAIL` lines: the lock is valid and generates, and `database_url` answers `SELECT 1` or the server binaries for `migrations` are found. Exits 1 if anything failed. |
| `watch` | yes | `migrations`, the config file | Regenerates on every change; needs `migrations` (a live `database_url` has nothing to watch). A failed generation is reported and the loop continues. |
| `prepare` | yes | `-queries file.json` | Prepares each query of a `qtest.Dump` file on a server: `$DATABASE_URL`, else `database_url`, else a throwaway server built from `migrations`. |
| `rows` | no | `-dir` (default `.`) | Works on a Go package directory. |
| `sql2go` | yes | `schema.lock` | `-e "SQL"` or files/stdin; `-q` (default `q`) is the name the qlx package is imported as; `-pkg` is the qualifier of the generated package (empty when dot-imported). |
| `regress` | yes | `schema.lock` | `-dir`, `-ledger`, `-cases`, `-baseline`, `-pkg`: translates PostgreSQL's regression SQL; a maintainer tool. |

Every command that reads the config accepts `-config` and, for `gen`,
`-from-lock`.

Exit codes: `0` success, `1` the command ran and failed, `2` bad usage or an
invalid config file.

### 2.2 `qlx vet` is gone

`qlx vet` exits with status 2 and points to the analyzer ([§4](#4-the-analyzer-qlxvet)),
so a CI step that still calls it cannot pass silently.

### 2.3 Finding the PostgreSQL binaries

To build the schema from `migrations`, `qlx` needs `postgres`, `initdb` and
`pg_ctl`. It looks, in this order:

1. `pg_bin` in `qlx.yaml`;
2. `$PGBIN`;
3. the newest `/usr/lib/postgresql/*/bin`;
4. `initdb` on `PATH`.

When run as root it starts the server as the `postgres` user, which the server
requires. If it finds nothing it says so: set `pg_bin` or `PGBIN`, or use
`database_url` instead.

The server it starts is temporary: unix socket only, in a directory under the
system temp directory, removed when the command ends.

## 3. Runtime options

All of these are plain Go values. The zero value of every options struct is
usable.

### 3.1 The dialect

```go
d := qlx.Dialect{Version: qlx.PG18}
```

`Dialect.Version` is the PostgreSQL major SQL is rendered for (`qlx.PG16` to
`qlx.PG19`). **The zero value is the newest supported version (19).** A
construct that does not exist in the chosen version fails with an error at
render time. With `pgxexec.Client` you do not set it by hand: `Connect` reads
`server_version_num` once and uses the server's own major, so a construct newer
than the server fails with `ErrUnsupportedByServer` before any network call.

### 3.2 `pgxexec.Connect`

```go
client, err := pgxexec.Connect(ctx, dsn, pgxexec.ConnectOptions{
    Mode:      pgxexec.CacheStatements,
    MinServer: 16,
    Spec:      &db.Spec,
    OnAhead:   func(server int, targets []int) { slog.Warn("ahead", "server", server) },
})
```

| Field | Default | Meaning |
|---|---|---|
| `Mode` | `CacheStatements` | How statements reach the server, see below. |
| `Tracer` | none | Observes every statement run through `Client.DB`. `pgxexec.Tracers` combines several. |
| `AfterConnect` | none | Runs on every new connection after the range codecs are registered. Generated code passes its type registration here. |
| `MinServer` | `0` (no check) | Lowest server major the application supports; `Connect` fails if the server is older. |
| `Spec` | none | The generated `SchemaSpec`. When set, `Connect` fails if the server is older than the oldest `targets`, and calls `OnAhead` if it is newer than every target (the code still works, but runs ahead of its pinned ledger). |
| `OnAhead` | none | Called with the server major and the targets when the server is ahead. |
| `Shapes` | `qlx.DefaultShapes` | A private shape cache for this client ([§3.5](#35-caches)). |

The connection string itself (`dsn`) is parsed by pgx: host, port, pool size
(`pool_max_conns`), timeouts and TLS are pgx and pgxpool settings, not QLX's.

**`PoolMode`** is how statements reach the server:

| Mode | Use it when |
|---|---|
| `CacheStatements` (default) | A direct connection or a session-mode pooler. Each statement is prepared once per connection (pgx's default). |
| `CacheDescribe` | Behind PgBouncer in **transaction** mode. Unnamed statements with a cached description. |
| `Simple` | A pooler that supports nothing else. Parameters are interpolated client-side by pgx. |

### 3.3 Transactions with retry: `pgxexec.InTx`

```go
err := pgxexec.InTx(ctx, pool, pgx.TxOptions{IsoLevel: pgx.Serializable},
    pgxexec.Retry{Attempts: 5, Base: 10 * time.Millisecond, Max: 5 * time.Second},
    func(ctx context.Context, tx pgx.Tx) error { /* ... */ return nil })
```

`InTx` runs the function again when the server reports a serialization failure
(`40001`) or a deadlock (`40P01`). Nothing else is retried. The function must
be safe to run again.

| Field | Default | Meaning |
|---|---|---|
| `Attempts` | `5` (also for `0` or negative) | Total tries, including the first. |
| `Base` | `10ms` (also for `0` or negative) | First wait; it doubles each time, with random jitter of up to half. |
| `Max` | `5s`, never below `Base` | Longest wait: the doubling stops here. |
| `OnRetry` | none | Called before each retry with the attempt that failed (1-based) and its error. Use it as a metric. |

### 3.4 Listening, bulk inserts

`pgxexec.ListenOptions` (for `ListenChan`):

| Field | Default | Meaning |
|---|---|---|
| `Buffer` | `64` | Capacity of the returned channel. When the consumer falls behind the listener blocks; PostgreSQL queues the rest. |
| `BackoffBase`, `BackoffMax` | `100ms`, `30s` | Wait between reconnect attempts, doubling with jitter. |
| `OnReconnect` | none | Called after each successful (re)subscription; `attempt` is `0` for the first. Notifications sent while the connection was down are lost: resynchronize here. |
| `OnError` | none | Reports a lost connection before the wait. |

`pgxexec.BulkOptions` (for `InsertMany` and `InsertManyReturning`):

| Field | Default | Meaning |
|---|---|---|
| `MaxParams` | `0` = `qlx.MaxBindParams` (65535) | Parameter budget of one statement. Lower it for rows built with `ToX` over expressions that carry arguments of their own. Several statements run in one transaction when more than one is needed. |

### 3.5 Caches

QLX renders each statement **shape** once and reuses the rendered SQL.

> **What is a "shape"?** A shape is the query's structural skeleton with values replaced by placeholders (`$1`, `$2`, ...). It is **not** a query execution or request count:
> - `WHERE id = 1` and `WHERE id = 2` produce the exact same shape (`WHERE id = $1`).
> - A query executed a billion times with different parameter values occupies **only one entry** in the cache.
> - Lists with variable lengths do not multiply shapes: `col.Any(slice)` and `col.In(slice)` both render `= ANY($1)`, keeping the shape identical regardless of slice length.
>
> 32,768 shapes is therefore immense: a typical production application has a few hundred distinct query structures. 32,768 easily accommodates applications with complex dynamic filtering ($n$ optional filters yield at most $2^n$ shapes for that endpoint). The ceiling is not preallocated: storing a few hundred shapes costs only a few kilobytes, and reaching the full ceiling takes only ~8–15 MB.

There are two caches:

| | Size | Notes |
|---|---|---|
| `qlx.DefaultShapes` | 32,768 shapes, per process | Used by `Resolve` and by every `pgxexec.Client` unless it has its own. |
| `qlx.NewShapeCache(max)` | `max`, at least 32 | A private cache; give it to a client with `ConnectOptions.Shapes`. |
| `qlx.NewCache(max)` | `max`, at least 1 | The older LRU keyed by a shape value you provide. |

`Stats()` returns hits, misses, evictions and size. A steadily growing eviction
count means the program builds an unbounded number of shapes (an `IN` list per
call, a column list taken from input): use `Expr.Any` with a slice instead.
`ShapeCache.OnThrash(fn)` calls `fn` once, the first time the cache has to
evict, with the counters at that moment: log from it and return. Pass `nil` to
remove it.

### 3.6 OpenTelemetry: `otelqlx`

```go
ins, err := otelqlx.New(
    otelqlx.WithTracerProvider(tp),
    otelqlx.WithMeterProvider(mp),
    otelqlx.WithQueryText(true),
    otelqlx.WithRecordErrors(false),
)
```

| Option | Default | Meaning |
|---|---|---|
| `WithTracerProvider(tp)` | the global provider | Tracer to use. |
| `WithMeterProvider(mp)` | the global provider | Meter to use. |
| `WithQueryText(on)` | `true` | Put `db.query.text` (the parameterized SQL, never the values) on spans. Turn it off when even query shapes are sensitive. |
| `WithRecordErrors(on)` | `false` | Also record the error message as a span event. Off by default: PostgreSQL error messages can contain row values. |

### 3.7 Test helpers: `qtest`

`qtest.RegressOptions` (for `RunRegress`): `Dialect`; `Normalize` (compares the
original and rendered SQL; when nil, or when it fails on the original, the live
server is the oracle through `Prepare`); `Prepare`; and `Known`, a map from case
ID to the reason it is expected to fail. A known failure does not fail the
test; a known failure that now passes does, so the list only shrinks.
`qtest.LoadKnown(path)` reads it from a `{"id": "reason"}` file; a missing file
is an empty set.

## 4. The analyzer (`qlxvet`)

Install it and run it as a vet tool or standalone:

```bash
go install github.com/noobmaisfier/qlx/analyzer/cmd/qlxvet@latest
go vet -vettool=$(which qlxvet) ./...
qlxvet ./...
```

| Flag | Default | Meaning |
|---|---|---|
| `-targets` | `18,19` | Comma-separated PostgreSQL majors the program must run on. A function, method or `EXPLAIN` option whose version range does not cover them is reported (V009). Keep it equal to `targets` in `qlx.yaml`. |
| `-audit` | `false` | Report every `//qlx:ignore` together with its reason (V011), to review suppressions. |

Example: `go vet -vettool=$(which qlxvet) -targets=16,17,18,19 ./...`

To silence one finding, put a comment on the same line or the line before, with a reason:

```go
//qlx:ignore the table name comes from a closed enum, not from input
```

A `//qlx:ignore` without a reason is itself a finding (V010). With `-audit`, every
suppression is reported with its reason (V011), so the count and the reasons can
be reviewed in CI output. The rules are listed in the guide.

The analyzer stays silent when it cannot resolve something, rather than guess.
It does not inspect the parts of `Copy*`, `Declare`, `Set`, `Cluster` and
`Reindex` described in [limits](limits.md).

## 5. Environment variables

### 5.1 For users

| Variable | Read by | Meaning |
|---|---|---|
| `DATABASE_URL` | `qlx verify`, `qlx prepare` | The database to check. Takes precedence over `database_url` in `qlx.yaml`. (`qlx gen` reads only the config file.) |
| `PGBIN` | `qlx gen` (migrations), `scripts/with_pg.sh` | Directory with the PostgreSQL server binaries. `pg_bin` in `qlx.yaml` wins. |

Connection parameters such as `PGHOST`, `PGPASSWORD` or `PGSSLMODE` are read by
pgx when your DSN leaves them out; they are not QLX settings.

### 5.2 For tests and development

These are used by the repository's own tests and scripts. You only need them if
you work on QLX itself (see [CONTRIBUTING](../CONTRIBUTING.md)).

| Variable | Meaning |
|---|---|
| `QLX_TEST_DSN` | Connection string for the `pgxexec` tests; those tests skip themselves when it is unset. |
| `QLX_PG_HOST`, `QLX_PG_DB`, `QLX_PG_USER`, `QLX_PG_VERSION` | Server used by the root-module tests. `scripts/with_pg.sh` sets them for you. `QLX_PG_VERSION` is the server's major. |
| `QLX_PG_URLS` | For `scripts/release.sh`: one server per major, `"16=postgres://... 17=postgres://... ..."`, to merge the catalog ledger. |
| `QLX_RELEASE` | `1` turns the "ledger lists every targeted major" check from a warning into a failure. Set by the release process. |
| `QLX_FUZZ_N`, `QLX_FUZZ_SEED`, `QLX_ODD_N`, `QLX_ODD_SEED`, `QLX_ODD_DIR` | Number of cases, seed and output directory of the fuzz and odd-schema generator tests. A failing run prints its seed. |
| `QLX_SCHEMA_DIR` | Extra directory of real-world schemas for the `pgxexec` real-schema test. |
| `QLX_VETTOOL` | Path to a built `qlxvet`, to run the analyzer inside the real-schema test. |
| `QLX_CI_CACHE` | Cache directory of `scripts/ci-local.sh`. |
| `GOWORK=off` | Build a module the way a user gets it, without `go.work` (see CONTRIBUTING). |

## 6. Which setting do I change?

| I want to... | Change |
|---|---|
| support PostgreSQL 16 and 17 as well | `targets: [16, 17, 18, 19]` in `qlx.yaml`, `-targets=16,17,18,19` for `qlxvet`, then `qlx gen` |
| generate from my running database instead of migrations | `database_url` in `qlx.yaml` (or `-from-lock` to use the committed lock) |
| fail CI when the generated code is stale | run `qlx check` |
| fail CI when production drifted from the lock | run `qlx verify` with `DATABASE_URL` set |
| use PgBouncer in transaction mode | `ConnectOptions{Mode: pgxexec.CacheDescribe}` |
| retry serialization failures | `pgxexec.InTx` with a `Retry` |
| see whether the shape cache is thrashing | `client.Shapes.Stats()` and `OnThrash` |
| keep query text out of traces | `otelqlx.WithQueryText(false)` |
| use `shopspring/decimal` for `numeric` | an `overrides` entry with `family: num` |
| read arrays that can hold NULL | `array_nulls: true` |
| read `infinity` timestamps | `timestamptz: qt` |
| expose IDs as opaque strings | `ids: string` and `qt.SetIDKey` at start-up |
